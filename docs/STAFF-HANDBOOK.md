## 1. จัดการแอดมิน

### เข้าแอดมินต้องมีสองอย่าง

1. **รหัส นศ. ของตัวเอง** ที่ถูกตั้งให้เป็นแอดมินไว้ในระบบ
2. **รหัสกลาง** หนึ่งตัวที่กรรมการทั้งชุดใช้ร่วมกัน

ขาดอย่างใดอย่างหนึ่งเข้าไม่ได้ — คนที่รู้รหัสกลางแต่ไม่ได้ถูกตั้งเป็นแอดมิน ใส่ยังไงก็ไม่ผ่าน
และคนที่ถูกตั้งเป็นแอดมินแต่ไม่รู้รหัสกลางก็เข้าไม่ได้เช่นกัน

เข้าที่ `https://<เว็บของคณะ>/fms-ovs/admin/login` แล้วกรอก:

```
Username   รหัส นศ. ของตัวเอง       เช่น 6610510149
Password   รหัสกลาง                 20 ตัวอักษรที่ระบบสุ่มให้
```

> ⚠️ **Password คือรหัสกลางล้วน ๆ** ไม่ต้องเอารหัส นศ. หรืออีเมลมาต่อข้างหน้า
> (ระบบรุ่นเก่าเคยต้องต่อกัน จนคนตั้งระบบล็อกตัวเองออกมาแล้ว — รุ่นนี้ไม่มีแล้ว)

### คำสั่งที่ใช้ทั้งหมด

```bash
node scripts/admin.js --list                    # ใครเป็นแอดมินบ้าง + รหัสกลางตั้งหรือยัง
node scripts/admin.js --grant 6610510149        # ตั้งให้เป็นแอดมิน
node scripts/admin.js --revoke 6610510149       # ถอดสิทธิ์ (มีผลทันที)
node scripts/admin.js --rotate-password         # ออกรหัสกลางใหม่
```

### เปลี่ยนรหัสผ่านแอดมิน

```bash
node scripts/admin.js --rotate-password
```

ระบบจะสุ่มรหัสใหม่แล้ว**แสดงบนจอครั้งเดียว** — คัดลอกเก็บทันทีก่อนปิดหน้าต่าง

สิ่งที่ต้องรู้:

- **รหัสเดิมใช้ไม่ได้ทันทีที่รันคำสั่งนี้** ทุกคนต้องได้รหัสใหม่ ไม่ใช่เฉพาะคนที่รัน
  → บอกกรรมการทุกคนก่อนกด ไม่งั้นจะมีคนล็อกอินไม่ได้กลางวันเลือกตั้ง
- **ไม่มีใครเปิดดูรหัสย้อนหลังได้** ระบบเก็บแค่ลายนิ้วมือของรหัส (bcrypt hash) ไม่ได้เก็บ
  ตัวรหัสไว้ที่ไหนเลย ลืมแล้วมีทางเดียวคือออกใหม่
- **ห้ามพิมพ์รหัสลงไฟล์ในโปรเจกต์ ลงเอกสาร หรือแชทกลุ่มที่ค้างอยู่นาน ๆ**
  ส่งแบบตัวต่อตัวแล้วให้ปลายทางเก็บลงตัวจัดการรหัสผ่าน

### เพิ่มแอดมินคนใหม่

```bash
node scripts/admin.js --grant <รหัส นศ. ของเขา>
```

เงื่อนไข: คนนั้นต้องมีข้อมูลอยู่ในระบบก่อน — ถ้าขึ้นว่า "ไม่พบ" ให้เขาล็อกอินหน้าเว็บ
ด้วย PSU Passport หนึ่งครั้ง (ระบบจะสร้างข้อมูลให้เอง) แล้วรันคำสั่งนี้ซ้ำ

จากนั้นบอกรหัสกลางให้เขา — **ไม่ต้องออกรหัสใหม่** รหัสกลางตัวเดิมใช้ได้กับทุกคนที่ถูกตั้งไว้

### ถอดแอดมิน (คนพ้นวาระ / ลาออก)

```bash
node scripts/admin.js --revoke <รหัส นศ. ของเขา>
```

มีผลกับคลิกถัดไปของเขาทันที ไม่ต้องรอ ไม่ต้องรีสตาร์ทอะไร แม้เขากำลังเปิดหน้าแอดมินค้างอยู่
หน้าจอจะเด้งกลับไปหน้าล็อกอินเอง

**ถ้าคนที่ถอดออกรู้รหัสกลาง ให้เปลี่ยนรหัสกลางด้วย** (`--rotate-password`) เพราะรหัสตัวเดิม
ยังอยู่ในหัวเขา — ถอดสิทธิ์อย่างเดียวพอสำหรับคนที่ยังไว้ใจได้ แต่ตอนส่งมอบชุดกรรมการ
ให้ทำทั้งสองอย่างเสมอ

### ส่งมอบให้กรรมการชุดใหม่ (ทำทุกปี)

```bash
node scripts/admin.js --list                   # ดูว่าชุดเก่ามีใคร
node scripts/admin.js --revoke <รหัสเดิม>       # ทีละคนจนหมด
node scripts/admin.js --grant  <รหัสใหม่>       # ทีละคน
node scripts/admin.js --rotate-password        # รหัสกลางใหม่ แจกเฉพาะชุดใหม่
node scripts/admin.js --list                   # ยืนยันว่าเหลือเฉพาะคนที่ตั้งใจ
```

### เข้าไม่ได้ทั้งทีม (ทางหนีไฟ)

```bash
node scripts/admin.js --break-glass
```

สร้างบัญชี `fmsadminstaff` ที่มีรหัสของตัวเองแยกจากรหัสกลาง ใช้ตอนฉุกเฉิน เช่น PSU SSO
ล่มวันเลือกตั้ง หรือรหัสกลางหายพร้อมกันทั้งทีม · บัญชีนี้**ลงคะแนนไม่ได้**โดยตั้งใจ
เพราะไม่มีชั้นปี ใช้เสร็จแล้วปิดด้วย `--revoke fmsadminstaff`

### สิ่งที่หน้าแอดมินทำไม่ได้ และตั้งใจให้เป็นแบบนั้น

การเพิ่ม/ถอดแอดมินและการเปลี่ยนรหัส **ไม่มีปุ่มในหน้าเว็บ** ต้องเข้าเครื่องเซิร์ฟเวอร์เท่านั้น
เพื่อไม่ให้ใครที่ยึดหน้าแอดมินได้ตั้งพรรคพวกตัวเองเป็นแอดมินเพิ่ม

## 2. ติดตั้งบนเซิร์ฟเวอร์ครั้งแรก

> รอบแรกควรทำคู่กับคนที่เคยติดตั้ง · ทุกข้อมีรายละเอียดเต็มใน
> [DEPLOY-CHECKLIST-2026.md](DEPLOY-CHECKLIST-2026.md) — ในนี้คือลำดับใหญ่ ๆ

### 2.1 ของที่ต้องมีก่อน

- เครื่อง Linux ที่ติดตั้ง Docker และ Docker Compose แล้ว
- PostgreSQL (จะให้ Docker สร้างให้ หรือขอจาก IT คณะก็ได้ — ใบขออยู่ที่
  [STAFF-DB-BRIEF-2026.md](STAFF-DB-BRIEF-2026.md))
- ค่า PSU SSO ปีนั้น (client id / client secret / redirect uri) จาก IT ม.อ.
- ไฟล์รายชื่อนักศึกษาผู้มีสิทธิ์

### 2.2 ตั้ง database

ถ้าใช้ Postgres ของคณะ ขอ 2 บัญชี (ดูใบขอ): `fms_migrate` สำหรับสร้าง/แก้โครงสร้าง
และ `fms_app` สำหรับตัวเว็บใช้จริง — แยกกันเพื่อให้เว็บ**เพิ่มบัตรได้แต่ลบบัตรไม่ได้**

สร้างโครงสร้างตาราง (รันจากเครื่องที่มีโค้ด ชี้ไปที่ database):

```bash
DATABASE_URL="<connection string ของ fms_migrate>" npx prisma migrate deploy
DATABASE_URL="<connection string ของ fms_migrate>" psql -f scripts/sql/ballot-grants.sql
```

`migrate deploy` สร้างตารางทั้งหมด · `ballot-grants.sql` คือตัวล็อกที่ทำให้ตารางบัตร
เพิ่มได้อย่างเดียว **ห้ามข้ามข้อนี้** มันคือเหตุผลที่ผลเลือกตั้งแก้ไม่ได้แม้ใครยึดเซิร์ฟเวอร์ได้

นำเข้ารายชื่อผู้มีสิทธิ์:

```bash
npm run import-students -- <ไฟล์รายชื่อ>
```

### 2.3 ตั้งค่า `.env` บนเซิร์ฟเวอร์

```
DATABASE_URL=              # ของ fms_app (ไม่ใช่ fms_migrate)
NEXTAUTH_SECRET=           # สุ่มใหม่: openssl rand -base64 32
NEXTAUTH_URL=              # URL จริง เช่น https://xxx.psu.ac.th/fms-ovs
NEXT_PUBLIC_BASE_PATH=/fms-ovs
ADMIN_JWT_SECRET=          # สุ่มใหม่: openssl rand -hex 32
AUTHENTIK_CLIENT_ID=
AUTHENTIK_CLIENT_SECRET=
AUTHENTIK_REDIRECT_URI=
ELECTION_BALLOT_PUBLIC_KEY=   # ได้จากข้อ 2.4
BALLOT_CHAIN_SECRET=          # ได้จากข้อ 2.4
```

**รหัสผ่านแอดมินไม่อยู่ในไฟล์นี้** อยู่ในฐานข้อมูล ตั้งด้วยคำสั่งใน §1

### 2.4 พิธีสร้างกุญแจบัตรลงคะแนน (ปีละครั้ง ~10 นาที)

ทำกับอาจารย์ที่ปรึกษา บนเครื่องที่ไว้ใจได้:

```bash
node scripts/generate-election-keys.js
```

ทำตามที่จอบอก: **public key + chain secret** ไปวางใน `.env` บนเซิร์ฟเวอร์ ·
**private key** เก็บออฟไลน์ (กระดาษ/USB) แบ่งกันถือระหว่างเจ้าหน้าที่กับอาจารย์
ห้ามอยู่บนเซิร์ฟเวอร์เด็ดขาด — ใช้เฉพาะกรณีมีข้อพิพาทแล้วต้องนับคะแนนใหม่ต่อหน้ากรรมการ

ถ้ากุญแจสองตัวบน `.env` ไม่ครบ ระบบจะ**ปิดรับโหวตทันที**แทนที่จะเก็บบัตรแบบไม่เข้ารหัส

### 2.5 เปิดระบบ

```bash
docker compose up -d --build
docker compose logs -f web        # ดูว่าขึ้นเรียบร้อยไหม (Ctrl+C เพื่อออกจาก log)
```

เช็คว่ารอด: เปิด `https://<เว็บ>/fms-ovs` แล้วหน้าแรกต้องขึ้นปกติ

> สถานะ ณ 2026-07-28: ทุกอย่างในหน้านี้ผ่านการรันจริงแล้ว **ยกเว้นสองคำสั่ง docker
> ข้างบนกับข้อ 3** ที่ยังไม่ได้รันกับโค้ดรุ่นล่าสุด (รอรอบทดสอบ docker ของทีมพัฒนา)
> — ถ้าติดตรงนี้ให้ถามทีมพัฒนาก่อน อย่าเดาเอง

### 2.6 ตั้งแอดมินชุดแรก

```bash
node scripts/admin.js --grant <รหัส นศ. ของกรรมการแต่ละคน>
node scripts/admin.js --rotate-password
node scripts/admin.js --list
```

### 2.7 ด่านสุดท้ายก่อนเปิดจริง

เข้าหน้าแอดมิน → ปุ่ม **"ตรวจความพร้อมระบบ"** ระบบเช็คให้เอง 14 ข้อ
(วันเวลา ผู้สมัคร รายชื่อผู้มีสิทธิ์ คะแนนเริ่มต้น การตั้งค่า) **ต้องไม่มีข้อสีแดง**

## 3. อัปเดตโค้ดรอบใหม่

ใช้เมื่อมีการแก้โค้ดแล้วต้องเอาขึ้นเซิร์ฟเวอร์

```bash
# 1. สำรองฐานข้อมูลก่อนเสมอ
sh scripts/backup.sh

# 2. ดึงโค้ดใหม่
git pull

# 3. ถ้ามีการแก้โครงสร้างฐานข้อมูล (คนส่งโค้ดจะบอก)
DATABASE_URL="<ของ fms_migrate>" npx prisma migrate deploy

# 4. build + เปิดใหม่
docker compose up -d --build

# 5. ดู log ว่าไม่มี error
docker compose logs -f web
```

เช็คหลังอัปเดตทุกครั้ง: หน้าแรกขึ้นปกติ · ล็อกอินแอดมินได้ · หน้าผลคะแนนไม่พัง

**ห้ามอัปเดตระหว่างที่การโหวตกำลังเปิด** ถ้าจำเป็นจริง ๆ ให้สลับโหมดเป็น `PAUSE`
ในหน้าแอดมินก่อน ทำเสร็จแล้วค่อยสลับกลับ

ถ้าอัปเดตแล้วพัง: `git checkout <commit เดิม>` แล้ว `docker compose up -d --build` ซ้ำ
ฐานข้อมูลไม่ได้ถูกแตะจากการ build จึงกลับไปรุ่นเดิมได้ทันที (ยกเว้นรอบที่มี migrate —
กรณีนั้นต้อง restore backup จากข้อ 1)

## 4. สิ่งที่ห้ามทำ

- **ห้ามแก้ข้อมูลในตาราง `Ballot` หรือ `ChainHead` ด้วยมือ** ระบบตรวจการแก้ไขได้ และ
  ถ้าโซ่ขาดจะพิสูจน์ความถูกต้องของผลไม่ได้อีกเลย
- **ห้ามเอา private key ของบัตรขึ้นเซิร์ฟเวอร์** ต่อให้สะดวกกว่า
- **ห้ามกดรีเซ็ตข้อมูลโดยไม่สำรอง DB ก่อน** (`sh scripts/backup.sh`)
- **ห้ามส่ง connection string หรือรหัสผ่านทางแชทกลุ่ม/อีเมลเปิด**
- **ห้ามใช้บัญชีแอดมินร่วมกันโดยไม่ตั้งชื่อคน** — ระบบบันทึกว่าใครสั่งอะไรจากรหัส นศ.
  ที่ล็อกอิน ถ้าทุกคนใช้รหัสเดียวกันสืบย้อนไม่ได้

## 5. เวลามีปัญหา

ก่อนโทรหาคนเขียนโค้ด เก็บสามอย่างนี้ให้ครบ จะแก้ได้เร็วขึ้นมาก:

1. เกิดตอนไหน กำลังทำอะไรอยู่
2. ข้อความ error บนจอ (ถ่ายรูป/คัดลอกมาทั้งบรรทัด)
3. `docker compose logs --tail 100 web` — 100 บรรทัดสุดท้ายจาก log

อาการที่เคยเจอมาแล้วพร้อมวิธีแก้อยู่ใน [MAINTENANCE-RUNBOOK.md](MAINTENANCE-RUNBOOK.md) §6
รวมถึง: ล็อกอินแอดมินไม่ได้ · PSU SSO ล่ม · เว็บขึ้น 502 · คะแนนดูไม่ตรง · รูปหาย

**เรื่องที่ต้องรีบที่สุดคือระบบล่มระหว่างเปิดหีบ** — สลับโหมดเป็น `PAUSE` ก่อนเป็นอันดับแรก
บัตรที่ลงไปแล้วปลอดภัย ไม่หาย ไม่ซ้ำ แล้วค่อยหาสาเหตุ
