## 1. คำสั่งเดียวจบ

```bash
sh scripts/setup.sh
```

ตรวจเครื่องมือ → ตรวจ `.env` → ติดตั้ง dependency → สร้างตารางฐานข้อมูล → ล็อกสิทธิ์ตารางบัตร
→ เปิดระบบด้วย docker → ตรวจว่าเว็บตอบจริง → แสดงรายชื่อแอดมิน

หยุดทันทีที่เจอปัญหาและบอกวิธีแก้เป็นภาษาคน รันซ้ำได้ไม่เสียหาย (ไม่ลบข้อมูล)

**อยากดูเฉย ๆ ว่าตอนนี้พร้อมแค่ไหน โดยไม่ให้มันแก้อะไรเลย:**

```bash
sh scripts/setup.sh --check
```

**ติดตั้งพร้อมตั้งแอดมินคนแรกไปในตัว:**

```bash
sh scripts/setup.sh --admin 6610510149
```

สคริปต์นี้จะไม่ทำ 3 อย่างให้ เพราะต้องมีคนตัดสินใจ: พิธีสร้างกุญแจบัตร ([§8.3](#83-พิธีสร้างกุญแจบัตร-ปีละครั้ง-10-นาที)) ·
นำเข้ารายชื่อนักศึกษา (ต้องมีไฟล์) · ลบข้อมูล ([§5](#5-ขึ้นปีใหม่))

## 2. ตารางคำสั่ง

### ต้องทำ

| คำสั่ง | ใช้ตอนไหน |
|---|---|
| `sh scripts/setup.sh` | ติดตั้งครั้งแรก · หลังอัปเดตโค้ด · เว็บล่มอยากให้กลับมา |
| `node scripts/admin.js --grant <รหัส นศ.>` | ตั้งกรรมการเป็นแอดมิน |
| `node scripts/admin.js --revoke <รหัส นศ.>` | ถอดสิทธิ์คนที่พ้นวาระ |
| `node scripts/admin.js --rotate-password` | ออกรหัสกลางใหม่ (ตอนส่งมอบชุดใหม่ หรือลืมรหัส) |
| `npm run import-students -- <ไฟล์รายชื่อ>` | นำเข้าผู้มีสิทธิ์เลือกตั้งปีนั้น |
| `node scripts/generate-election-keys.js` | พิธีสร้างกุญแจบัตร ปีละครั้ง ทำกับอาจารย์ที่ปรึกษา |
| `sh scripts/backup.sh` | สำรองข้อมูล — **ทำก่อนทุกครั้งที่จะลบหรืออัปเดต** |
| `npm run preflight` | ตรวจความพร้อมก่อนเปิดหีบ |
| `node scripts/reconcile-scores.js` | ตรวจคะแนนหลังปิดหีบ ก่อนประกาศผล |

### ควรรู้ ใช้เมื่อจำเป็น

| คำสั่ง | ใช้ตอนไหน |
|---|---|
| `sh scripts/setup.sh --check` | อยากรู้สถานะโดยไม่แก้อะไร |
| `node scripts/admin.js --list` | ใครเป็นแอดมินบ้าง รหัสกลางตั้งหรือยัง |
| `node scripts/admin.js --break-glass` | ทีมล็อกอินไม่ได้ทั้งหมด ต้องการบัญชีสำรอง |
| `node scripts/verify-ballot-chain.js` | มีคนตั้งคำถามกับผล — พิสูจน์ว่าบัตรไม่ถูกแก้ |
| `npm run archive-year` | เก็บผลปีเก่าก่อนล้างข้อมูล |
| `docker compose logs --tail 100 web` | ดู log ตอนระบบมีปัญหา |
| `docker compose restart web` | เว็บค้าง อยากรีสตาร์ทอย่างเดียว ไม่ build ใหม่ |
| `psql "<fms_migrate>" -f scripts/sql/annual-reset.sql` | ล้างข้อมูลขึ้นปีใหม่ ([§5](#5-ขึ้นปีใหม่)) |

### ห้ามลืม

- **สำรองข้อมูลก่อนลบหรืออัปเดตเสมอ** — `sh scripts/backup.sh`
- **ปิดหีบเสร็จให้ถอดแอดมินชุดเก่าและเปลี่ยนรหัสกลาง** ([§3](#3-แอดมิน))
- **กระดาษ private key ห้ามอยู่บนเซิร์ฟเวอร์** ([§8.3](#83-พิธีสร้างกุญแจบัตร-ปีละครั้ง-10-นาที))

## 3. แอดมิน

### เข้าระบบต้องมีสองอย่าง

1. **รหัส นศ. ของตัวเอง** ที่ถูกตั้งเป็นแอดมินไว้
2. **รหัสกลาง** หนึ่งตัวที่กรรมการทั้งชุดใช้ร่วมกัน

ขาดอย่างใดอย่างหนึ่งเข้าไม่ได้ — รู้รหัสกลางแต่ไม่ได้ถูกตั้งเป็นแอดมิน ก็เข้าไม่ได้

เข้าที่ `https://<เว็บของคณะ>/fms-ovs/admin/login`

```
Username   รหัส นศ. ของตัวเอง       เช่น 6610510149
Password   รหัสกลาง                 20 ตัวอักษรที่ระบบสุ่มให้
```

> ⚠️ **Password คือรหัสกลางล้วน ๆ** ไม่ต้องเอารหัส นศ. หรืออีเมลมาต่อข้างหน้า

### เพิ่มแอดมิน

```bash
node scripts/admin.js --grant 6610510149
```

ถ้าขึ้นว่า "ไม่พบ" ให้คนนั้นล็อกอินหน้าเว็บด้วย PSU Passport หนึ่งครั้งก่อน แล้วรันซ้ำ
จากนั้นบอกรหัสกลางให้เขา — ไม่ต้องออกรหัสใหม่ รหัสเดิมใช้ได้กับทุกคนที่ถูกตั้งไว้

### ถอดแอดมิน

```bash
node scripts/admin.js --revoke 6610510149
```

มีผลกับคลิกถัดไปของเขาทันที แม้กำลังเปิดหน้าแอดมินค้างอยู่ก็จะเด้งออก
**ถ้าเขารู้รหัสกลาง ให้เปลี่ยนรหัสกลางด้วย**

### เปลี่ยนรหัสผ่าน

```bash
node scripts/admin.js --rotate-password
```

- รหัสใหม่ขึ้นบนจอ **ครั้งเดียว** คัดลอกเก็บก่อนปิดหน้าต่าง
- **รหัสเดิมตายทันทีที่กด** ทุกคนต้องได้รหัสใหม่ → บอกกรรมการก่อนกดเสมอ
- ไม่มีใครเปิดดูย้อนหลังได้ ระบบเก็บแค่ลายนิ้วมือของรหัส ลืมแล้วออกใหม่อย่างเดียว
- ห้ามพิมพ์ลงไฟล์ในโปรเจกต์ ลงเอกสาร หรือแชทกลุ่มที่ค้างนาน ๆ

### ส่งมอบให้กรรมการชุดใหม่ (ทำทุกปี)

```bash
node scripts/admin.js --list                   # ชุดเก่ามีใคร
node scripts/admin.js --revoke <รหัสเดิม>       # ทีละคนจนหมด
node scripts/admin.js --grant  <รหัสใหม่>       # ทีละคน
node scripts/admin.js --rotate-password        # รหัสใหม่ แจกเฉพาะชุดใหม่
node scripts/admin.js --list                   # ยืนยันว่าเหลือเฉพาะคนที่ตั้งใจ
```

### ทีมเข้าไม่ได้ทั้งหมด

```bash
node scripts/admin.js --break-glass
```

สร้างบัญชี `fmsadminstaff` ที่มีรหัสของตัวเองแยกจากรหัสกลาง · บัญชีนี้ลงคะแนนไม่ได้โดยตั้งใจ
ใช้เสร็จปิดด้วย `node scripts/admin.js --revoke fmsadminstaff`

### ทำไมไม่มีปุ่มในหน้าเว็บ

การเพิ่ม/ถอดแอดมินและเปลี่ยนรหัสทำได้จากเครื่องเซิร์ฟเวอร์เท่านั้น เพื่อไม่ให้คนที่แอบเข้า
หน้าแอดมินได้ตั้งพวกตัวเองเป็นแอดมินเพิ่ม

## 4. เลือกตั้งหนึ่งรอบ

### ก่อนเลือกตั้ง (เผื่อเวลา 1-2 สัปดาห์)

1. **เตรียมข้อมูลปีใหม่**

   ```bash
   npm run archive-year                       # เก็บผลปีที่แล้ว
   npm run import-students -- <ไฟล์รายชื่อ>    # นำเข้าผู้มีสิทธิ์
   npm run preflight                          # เช็คความพร้อม
   ```

2. **ตั้งค่าในหน้า admin** (ไม่ต้องแตะโค้ด): วันเวลาเลือกตั้ง · ปีการศึกษา · ชื่องาน ·
   พรรคและสมาชิก · ลิงก์แบบประเมิน · เลือกหน้าตาเว็บของปีนั้น

3. **พิธีสร้างกุญแจบัตร** — [§8.3](#83-พิธีสร้างกุญแจบัตร-ปีละครั้ง-10-นาที)

4. **ส่งมอบสิทธิ์แอดมินให้กรรมการชุดปีนี้** — [§3](#3-แอดมิน)

5. **กดปุ่ม "ตรวจความพร้อมระบบ" ในหน้า admin** เป็นด่านสุดท้าย ระบบเช็คเอง 14 ข้อ
   **ต้องไม่มีข้อสีแดง**

### วันเลือกตั้ง

ปกติไม่ต้องทำอะไร ระบบเปิด-ปิดตามเวลาเอง

- หน้า admin โชว์จำนวนผู้ใช้สิทธิ์แบบ real-time
- **ฉุกเฉิน:** สลับโหมดเป็น `PAUSE` ในหน้า admin — หยุดรับโหวตทันที แก้เสร็จสลับกลับ `AUTO`
- หน้า admin ไม่มีปุ่มลบข้อมูลใด ๆ ระบบลบบัตรที่ลงไปแล้วไม่ได้ทั้งเส้นทาง ไม่ต้องกลัวมือลั่น

### หลังปิดหีบ

```bash
node scripts/reconcile-scores.js     # คะแนน-จำนวนบัตร-โซ่ ต้องตรงกันทั้งสามทาง
```

ตรงกันแล้วจึงกด **"เปิดเผยผล"** ในหน้า admin → ผลนิ่งแล้วกด **"รับรองผล"**
(ทำครั้งเดียว ย้อนไม่ได้) → ถอดแอดมินชุดนี้ + เปลี่ยนรหัสกลาง ([§3](#3-แอดมิน)) เป็นอันจบปี

ถ้ามีคนตั้งคำถามกับผลคะแนน:

```bash
node scripts/verify-ballot-chain.js
```

พิสูจน์ได้ทันทีว่าบัตรทุกใบไม่ถูกแก้ · ถ้าถึงขั้นต้องนับใหม่ ใช้กระดาษ private key กับ
`scripts/decrypt-recount.js` แบบ offline ต่อหน้ากรรมการ

## 5. ขึ้นปีใหม่

**หน้าเว็บไม่มีปุ่มลบข้อมูล ตั้งใจให้เป็นแบบนั้น** — บัญชีฐานข้อมูลที่เว็บใช้ถูกตั้งให้
เพิ่มบัตรได้แต่ลบบัตรไม่ได้ ต่อให้มีคนแอบเข้าหน้าแอดมินได้ ก็ล้างผลที่กำลังเดินอยู่ไม่ได้

```bash
# 1. สำรองก่อน — ลบแล้วกู้ไม่ได้
sh scripts/backup.sh

# 2. ล้าง (ใช้บัญชี fms_migrate ไม่ใช่ของเว็บ)
psql "<connection string ของ fms_migrate>" -f scripts/sql/annual-reset.sql

# 3. ยืนยันว่าเป็นศูนย์จริง
npm run preflight
```

ค่าเริ่มต้นคือล้างคะแนน บัตร และคืนสิทธิ์โหวต **แต่เก็บรายชื่อพรรคไว้**
ถ้าจะลบพรรคชุดเก่าด้วย ให้เปิดคอมเมนต์สามบรรทัดท้ายไฟล์ตามที่เขียนไว้ในนั้น

> เก็บไฟล์ backup ของปีเก่าไว้อย่างน้อยหนึ่งปี — บัตรที่ลบแล้วนับใหม่ไม่ได้อีกเลย

## 6. อัปเดตโค้ด

```bash
sh scripts/backup.sh          # 1. สำรองก่อนเสมอ
git pull                      # 2. ดึงโค้ดใหม่
sh scripts/setup.sh           # 3. ที่เหลือสคริปต์จัดการให้ (migrate + build + เปิดใหม่)
```

เช็คหลังอัปเดต: หน้าแรกขึ้นปกติ · ล็อกอินแอดมินได้ · หน้าผลคะแนนไม่พัง

**ห้ามอัปเดตระหว่างการโหวตกำลังเปิด** ถ้าจำเป็นจริง ๆ สลับโหมดเป็น `PAUSE` ก่อน

ถ้าอัปเดตแล้วพัง:

```bash
git checkout <commit เดิม>
sh scripts/setup.sh
```

ฐานข้อมูลไม่ได้ถูกแตะจากการ build จึงกลับรุ่นเดิมได้ทันที (ยกเว้นรอบที่มีการแก้โครงสร้าง
ฐานข้อมูล — กรณีนั้นต้องกู้จาก backup ข้อ 1)

## 7. มีปัญหา

ก่อนโทรหาคนเขียนโค้ด เก็บสามอย่างนี้ให้ครบ จะแก้ได้เร็วขึ้นมาก:

1. เกิดตอนไหน กำลังทำอะไรอยู่
2. ข้อความ error บนจอ (ถ่ายรูป/คัดลอกทั้งบรรทัด)
3. `docker compose logs --tail 100 web`

| อาการ | ลองก่อน |
|---|---|
| เว็บเปิดไม่ขึ้น / 502 | `sh scripts/setup.sh --check` แล้วดูข้อที่ไม่ผ่าน |
| เว็บค้าง ช้าผิดปกติ | `docker compose restart web` |
| ล็อกอินแอดมินไม่ได้ | `node scripts/admin.js --list` — มีชื่อไหม รหัสกลางตั้งหรือยัง |
| ลืมรหัสกลาง | `node scripts/admin.js --rotate-password` แล้วแจกใหม่ทั้งทีม |
| นักศึกษาล็อกอินไม่ได้ทั้งระบบ | PSU SSO ฝั่งมหาวิทยาลัย — ติดต่อ IT ม.อ. ขอค่าใหม่ |
| โหวตไม่ได้ ทั้งที่ยังไม่ถึงเวลาปิด | กุญแจบัตรใน `.env` ไม่ครบ → `sh scripts/setup.sh --check` |
| คะแนนดูไม่ตรง | `node scripts/reconcile-scores.js` |

**เรื่องที่ต้องรีบที่สุดคือระบบล่มระหว่างเปิดหีบ** — สลับโหมดเป็น `PAUSE` ก่อนเป็นอันดับแรก
บัตรที่ลงไปแล้วปลอดภัย ไม่หาย ไม่ซ้ำ แล้วค่อยหาสาเหตุ

อาการที่ลึกกว่านี้พร้อมวิธีแก้ทีละขั้นอยู่ใน `docs/MAINTENANCE-RUNBOOK.md` §6 (ฉบับช่างเทคนิค)

## 8. ติดตั้งครั้งแรก (ทำครั้งเดียว)

### 8.1 ของที่ต้องมีก่อน

- เครื่อง Linux ที่มี Docker และ Docker Compose
- PostgreSQL — ขอจาก IT คณะ ([§8.5](#85-ใบขอ-database-คัดลอกส่ง-it-คณะ) คัดลอกส่งได้เลย)
- ค่า PSU SSO ปีนั้น (client id / client secret / redirect uri) จาก IT ม.อ.
- ไฟล์รายชื่อนักศึกษาผู้มีสิทธิ์

### 8.2 ตั้งค่า `.env`

สร้างไฟล์ `.env` ในโฟลเดอร์โปรเจกต์:

```
DATABASE_URL=              # ของบัญชี fms_app (บัญชีที่เว็บใช้)
```

### 8.3 พิธีสร้างกุญแจบัตร (ปีละครั้ง ~10 นาที)

ทำกับอาจารย์ที่ปรึกษา บนเครื่องที่ไว้ใจได้:

```bash
node scripts/generate-election-keys.js
```

ทำตามที่จอบอก:

- **public key + chain secret** → วางใน `.env` บนเซิร์ฟเวอร์
- **private key** → เก็บออฟไลน์ (กระดาษ/USB) แบ่งกันถือระหว่างเจ้าหน้าที่กับอาจารย์
  **ห้ามอยู่บนเซิร์ฟเวอร์เด็ดขาด** ใช้เฉพาะกรณีมีข้อพิพาทแล้วต้องนับคะแนนใหม่ต่อหน้ากรรมการ
  ถ้าหาย ผลเลือกตั้งไม่เสีย เสียแค่ความสามารถนับใหม่

> ⚠️ **ห้ามใช้กุญแจของเครื่องทดสอบบนเครื่องจริง** และเปลี่ยนกุญแจได้ก่อนบัตรใบแรกลงกล่อง
> เท่านั้น — เปลี่ยนทีหลังบัตรเก่าจะเปิดด้วยกุญแจใหม่ไม่ได้
>
> ถ้ากุญแจสองตัวใน `.env` ไม่ครบ ระบบจะปิดรับโหวตทันที แทนที่จะเก็บบัตรแบบไม่เข้ารหัส

### 8.4 ติดตั้งและเปิดระบบ

```bash
sh scripts/setup.sh --admin <รหัส นศ. ของคุณ>
```

จบในคำสั่งเดียว ([§1](#1-คำสั่งเดียวจบ)) เหลือแค่นำเข้ารายชื่อ ตั้งค่าในหน้า admin
แล้วกดปุ่มตรวจความพร้อม

### 8.5 ใบขอ database (คัดลอกส่ง IT คณะ)

> **เรื่อง: ขอ PostgreSQL database — ระบบเลือกตั้งออนไลน์ สโมสรนักศึกษา คณะวิทยาการจัดการ**
>
> **สิ่งที่ขอ**
>
> 1. **PostgreSQL 1 database** ชื่อแนะนำ `fms_election` (เวอร์ชันเดิมที่คณะใช้ได้
>    ระบบใช้ Prisma ORM มาตรฐาน ไม่มี extension พิเศษ)
> 2. **สร้าง role 2 ตัว** (จุดที่ต่างจากปีก่อน — แยกสิทธิ์เพื่อความปลอดภัยของบัตรเลือกตั้ง):
>    - `fms_migrate` — เจ้าของ schema ใช้ตอนติดตั้ง/อัปเดตโครงสร้างเท่านั้น
>    - `fms_app` — role ที่ตัวเว็บใช้จริง สิทธิ์จำกัด (ทีมพัฒนารัน
>      `scripts/sql/ballot-grants.sql` กำหนดสิทธิ์เองหลัง migrate — ผลคือแอป
>      **เพิ่มบัตรได้แต่แก้/ลบบัตรไม่ได้เชิงโครงสร้าง**)
> 3. ส่ง **connection string ของทั้ง 2 role** ผ่านช่องทางปลอดภัย (ไม่ส่งแชท/อีเมลเปิด)
> 4. **Timezone** ของเครื่อง/container ตั้ง `Asia/Bangkok` (ตัวระบบ pin เวลาไทยในโค้ดแล้ว
>    ข้อนี้กันความสับสนเวลาอ่าน log เท่านั้น)
> 5. **Backup รายวันตามมาตรฐานคณะ** — ข้อมูลปีนี้อ่อนไหวน้อยกว่าปีก่อนมาก บัตรลงคะแนน
>    ถูกเข้ารหัสและไม่ผูกกับตัวผู้โหวตตั้งแต่ชั้นโครงสร้าง (ใน backup ก็ไม่มีข้อมูลว่าใครเลือกใคร)
>
> **สิ่งที่ไม่ต้องทำ**
>
> - ไม่ต้อง restore ข้อมูลปีก่อน — เริ่ม database ใหม่ทุกปี (รายชื่อผู้มีสิทธิ์ทีมพัฒนา import เอง)
> - ไม่ต้องเปิด public access — แอปกับ DB คุยกันภายใน (Docker network / localhost)
> - ไม่ต้องติดตั้งอะไรใน DB — migration ทีมพัฒนารันเองด้วย role `fms_migrate`

## 9. ห้ามทำ

- **ห้ามแก้ข้อมูลในตาราง `Ballot` หรือ `ChainHead` ด้วยมือ** ระบบตรวจการแก้ไขได้ และถ้าโซ่ขาด
  จะพิสูจน์ความถูกต้องของผลไม่ได้อีกเลย
- **ห้ามเอา private key ของบัตรขึ้นเซิร์ฟเวอร์** ต่อให้สะดวกกว่า
- **ห้ามลบข้อมูลโดยไม่สำรองก่อน** (`sh scripts/backup.sh`)
- **ห้ามส่ง connection string หรือรหัสผ่านทางแชทกลุ่ม/อีเมลเปิด**
- **ห้ามอัปเดตโค้ดระหว่างการโหวตกำลังเปิด**
