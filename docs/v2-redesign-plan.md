## สถานะ ballot-official (ตัวแรก)

ครบทุกหน้าแล้ว: หน้าแรก, ลงคะแนน (หลายพรรค/พรรคเดียว), พรรค, ผู้สมัคร, สำเร็จ, ผลคะแนน, สถานะระบบ, เข้าสู่ระบบ
เปิดดูได้ที่ `/template-preview?slug=ballot-official&page=<หน้า>&interact=1`

| หน้า | ลิงก์ทดสอบที่ควรเปิด |
|---|---|
| ผลคะแนน | `page=results` (ประกาศแล้ว) · `&variant=sealed` (หีบปิดผนึก) · `&variant=before` (ยังไม่เปิดหีบ) · `&variant=single` (พรรคเดียว) |
| สถานะระบบ | `page=closed&variant=waiting` · `ended` · `closed` (หยุดชั่วคราว) |
| เข้าสู่ระบบ | `page=login` · `&variant=mock` (โหมดทดสอบ) · `&variant=error` |

ผ่านเป็นต้นแบบอ้างอิงแล้ว รวมหน้าพรรคเดียว — commit `9cb4c73`

## บทเรียนจากตัวแรก ที่จะใช้กับทุกตัว

1. **หนึ่งหน้า หนึ่งของเด่น** ที่เหลือเงียบ — ที่คุณชอบคือบัตรยืนในหีบ ที่ไม่ชอบคือของเยอะ (กระดานขีดคะแนน) และตัวเลข "50" ยักษ์
2. **ทุก template ต้องมี "วัตถุ" ของตัวเอง** ที่เล่าเรื่องเดียวกันตั้งแต่หน้าแรกถึงหน้าผล ballot-official คือบัตร → หีบออนไลน์ → ต้นขั้ว
3. **ตัวอักษรไม่มีหัว** สำหรับหัวข้อและ UI มีหัวเฉพาะเนื้อหายาว — ตอนนี้หลายตัวใช้ Kanit, Anuphan, Chakra Petch, IBM Plex, Instrument Serif ปนกัน
4. **ห้ามเขียนข้อความที่ admin แก้ได้ลงในโค้ด** — เจอแล้วใน Studio Dark (ประโยคภาษาอังกฤษ "A vote that decides who leads your faculty…" เขียนตายในหน้าแรก)
5. **ภาษาไทยก่อน** — Gumroad/Studio Dark มีปุ่มและป้ายภาษาอังกฤษหลายจุด ("SIGN IN", "Meet Candidates", marquee "CAST YOUR VOTE")

## งานพื้นฐานก่อนเริ่มตัวที่ 2 (ประมาณครึ่งวัน)

ถ้าไม่ทำตรงนี้ แต่ละตัวจะใช้เวลาเท่าตัวแรก (ราว 1.5 วัน) ซึ่งไม่พอสำหรับ 6 ตัวในสัปดาห์นี้

- **แยกเนื้อหาพรรคที่ทุกตัวต้องมีเหมือนกัน** ออกมาเป็นชิ้นกลาง (`components/v2/shared/`): การเรียงทีมตามตำแหน่ง (นายก → รองนายก → ที่เหลือ), กติกา "ภาพกิจกรรมขึ้นเมื่อมีภาพหมู่มากกว่า 1 รูป", กติกา "ช่องทางติดต่อขึ้นเมื่อกรอกไว้", หน้าต่างดูสมาชิก, หน้าต่างดูภาพ แต่ละ template จะเหลือแค่แต่งหน้าตา
- **ให้หน้า results/closed/login เลือก v2 ก่อนทุก family** — ตอนนี้ผมเสียบ v2 ไว้ในกิ่งของ fms-official เท่านั้น (เพราะ ballot-official ต่อยอดจากมัน) ตัวถัดไปต่อยอดจาก family อื่น จึงต้องย้ายการเลือกขึ้นไปไว้บนสุดก่อน
- ย้ายฟังก์ชันสถานะการเลือกตั้ง (`useElectionStatus`) ที่ใช้แล้วใน ballot-official ไปใช้ทุกตัว — ทุกหน้าจะบอกสถานะตรงกัน

## 6 ตัวที่เหลือ (ตามลำดับที่คุณให้ไว้)

แต่ละตัวมี 2 ทาง ผมแนะนำทางแรก ถ้าไม่ชอบทั้งคู่บอกได้เลย

### 1. Verdure → v2

**ตอนนี้:** นิตยสาร สีเขียว ตราวงกลม "50" ใหญ่กลางหน้า เมนูลอยด้านล่างซ้ำกับเมนูบน ตัวอักษรมีเชิง
**ปัญหา:** ตัวเลขยักษ์ (แบบที่คุณไม่ชอบ), เมนูสองชุด, หัวข้อภาษาอังกฤษ "FMS Student Council Election"
**เก็บไว้:** intro ห้องลงคะแนนในหน้าพรรคเดียว (VerdureSingleParty) ที่คุณบอกว่าดีแล้ว, โทนเขียว, 4 โทนสีที่เลือกได้

- **ทาง A (แนะนำ) — "ทุกเสียงคือเมล็ด"**: หน้าแรกเป็นแปลงต้นไม้ที่งอกตามจำนวนคนมาใช้สิทธิ์จริง (ยิ่งมาเยอะยิ่งเขียว) การส่งบัตรคือหย่อนเมล็ดลงดิน หน้าสำเร็จคือต้นกล้าของคุณ หน้าผลคือสวนที่โตเต็ม — เล่าเรื่อง "การมีส่วนร่วม" ได้ชัดโดยไม่ต้องใช้ตัวเลขยักษ์
- ทาง B — "ตราประทับ": เก็บตราวงกลมไว้เป็นวัตถุหลัก การลงคะแนนคือการกดตรา ข้อเสีย: ตราประทับซ้ำกับ ballot-official

### 2. Gumroad → v2

**ตอนนี้:** neo-brutalist ขอบดำหนา สีจัด 6 โทน แถบวิ่ง กล่องสถิติแบบ bento
**ปัญหา:** "SAMO / 50" ซ้อนตัวใหญ่, กล่องสถิติหน้าตาเหมือนเว็บ SaaS, ภาษาอังกฤษเยอะ, แถบวิ่งแย่งสายตา
**เก็บไว้:** ขอบหนา เงาคม สีจัด 6 โทน (เป็นตัวเดียวที่สนุกแบบนี้)

- **ทาง A (แนะนำ) — "สติกเกอร์หาเสียง"**: หน้าแรกเป็นแผ่นสติกเกอร์ของแต่ละพรรค หน้าสำเร็จได้สติกเกอร์ **"ฉันไปใช้สิทธิ์แล้ว"** ที่เซฟไปลงสตอรี่ได้ (ไม่บอกว่าเลือกใคร) — ช่วยดึงคนมาเลือกตั้งเพิ่มจริง ๆ ซึ่งไม่มี template ไหนทำ
- ทาง B — "ป้ายหาเสียงริมทาง": โปสเตอร์ของพรรคติดบอร์ดเรียงกัน ข้อเสีย: ใกล้กับกระดานประกาศที่คุณไม่ชอบ

### 3. Blossom → v2

**ตอนนี้:** ชมพู หัวข้อใหญ่สองบรรทัด ตัวอักษรวงกลมหมุน "50" โปสเตอร์เอียงมุมขวาล่าง
**ปัญหา:** หน้าแรกมีแต่ตัวหนังสือ, คำเดียวในหัวข้อเป็นสีชมพู (ลูกเล่นที่เห็นบ่อยจนดูสำเร็จรูป), โปสเตอร์ถูกบังครึ่ง
**เก็บไว้:** โทนชมพูอ่อนโยน ความนุ่มนวล

- **ทาง A (แนะนำ) — "จดหมายเชิญ"**: หน้าแรกเป็นซองจดหมายจ่าหน้าถึงนักศึกษาคณะ (ชื่อคณะจากตั้งค่าทั่วไป) เปิดออกเป็นจดหมายเชิญไปใช้สิทธิ์ การส่งบัตรคือพับใส่ซองแล้วปิดผนึกด้วยครั่ง หน้าสำเร็จเป็นตราไปรษณีย์ "ส่งถึงแล้ว"
- ทาง B — "ช่อดอกไม้": แต่ละพรรคเป็นดอก ข้อเสีย: ชนกับ Verdure ทาง A (ธรรมชาติเหมือนกัน)

### 4. Receipt → v2

**ตอนนี้:** โต๊ะกระดาษ ใบเสร็จ สมุดจด ชิ้นกระดาษวางกระจาย
**ปัญหา:** ของกระจายเต็มหน้า (แบบที่คุณเรียกว่ารก), ปฏิทินขวาบนนับถอยหลัง **"เจอกันปีหน้า" 345 วัน** หลังปิดหีบ (นับไปปีหน้าเอง ทั้งที่ยังไม่มีใครตั้งวันเลือกตั้งปีหน้า — v2 ใช้ `useElectionStatus` ที่ไม่นับข้ามปี), ตัวอักษร Chakra Petch
**เก็บไว้:** ใบเสร็จที่หน้าสำเร็จ (animation รับบัตร)

- **ทาง A (แนะนำ) — "บัตรคิว"**: หน้าแรกมีเครื่องกดบัตรคิวชิ้นเดียว ตัวเลขบนบัตรคือจำนวนคนที่มาใช้สิทธิ์แล้ว ("คุณจะเป็นคนที่ 343") หน้าสำเร็จเครื่องพิมพ์ใบเสร็จออกมาจากช่อง — วัตถุเดียว เรียบกว่าเดิมมาก
- ทาง B — เก็บโต๊ะกระดาษแต่ลดเหลือ 1 ชิ้นต่อหน้า

### 5. Original → v2

**ตอนนี้:** ตัวที่ใช้จริงปีที่แล้ว การ์ดหลายใบ ไล่สี มีเงาเรือง นับถอยหลังด้านบน โปสเตอร์ขวา
**ปัญหา:** การ์ดโค้งเงาเท่ากันทุกใบ ไล่สีเป็นของตกแต่ง ตัวอักษร Inter
**ข้อควรระวัง:** คนเคยเห็นแล้วปีที่แล้ว เปลี่ยนมากไปอาจเสียความคุ้นเคย

- **ทาง A (แนะนำ) — "Original ที่เรียบขึ้น"**: โครงเดิมที่คนจำได้ (ซ้ายหัวข้อ + ปุ่ม, ขวาโปสเตอร์ + ตัวเลข) แต่ให้โปสเตอร์เป็นของเด่นชิ้นเดียว ลดการ์ดจาก 6 เหลือ 2 ตัดเงาเรืองและไล่สี — งานน้อยสุดใน 6 ตัว
- ทาง B — เปลี่ยนเป็นโลกใหม่เหมือนตัวอื่น

### 6. Studio Dark → v2

**ตอนนี้:** พื้นดำ สีเขียวมะนาว แถบข้างซ้าย หัวข้อภาษาอังกฤษตัวเอียง
**ปัญหา:** พื้นดำ + เขียวมะนาวเป็นโทนที่เว็บสำเร็จรูปใช้กันมาก, **ประโยคภาษาอังกฤษเขียนตายในโค้ด** (ขัดกฎ), แถบข้างกินที่บนมือถือ
**เก็บไว้:** ธีมมืดเพียงตัวเดียวในชุด

- **ทาง A (แนะนำ) — "คืนดีเบต"**: เวทีมืด สปอตไลท์ส่องทีละพรรคเหมือนคืนดีเบตหาเสียง ส่งบัตรแล้วไฟเวทีสว่างขึ้น หน้าผลคือไฟส่องผู้ชนะ เปลี่ยนสีจากเขียวมะนาวเป็นแสงไฟอุ่น
- ทาง B — "ห้องนับคะแนนกลางคืน": จอนับคะแนนสด ข้อเสีย: หน้าผลเปิดได้หลังปิดหีบเท่านั้น จอสดจึงว่างเกือบตลอด

## สิ่งที่ตกลงแล้ว (29 ก.ย.)

**ลำดับ (milestone ไม่ใช่วัน):**
Phase 0 โครงสร้างกลาง → Phase 1 Verdure (พิสูจน์โครงสร้าง) → Phase 2 Receipt (วัตถุที่มี interaction เยอะ) → Phase 3 Gumroad (ภาพจัด brutalist) → Phase 4 Blossom (โทนนุ่มแบบ editorial) → Phase 5 Original / Studio Dark

**ปรับจากทาง A ที่เสนอ:**
- **Verdure** — สวนคือสภาพของการมีส่วนร่วม ไม่ใช่ dashboard ไม่มีการนับเป็นต้นไม้ ตัวเลขผู้มาใช้สิทธิ์อยู่เป็นคำบรรยายเล็กใต้สวน สวนโตตามจำนวนรวมเท่านั้น ห้ามแบ่งแปลงตามพรรค (กฎข้อ 7)
- **Receipt** — ตู้บัตรคิวชิ้นเดียว หน้าแรกบอกจำนวนผู้มาใช้สิทธิ์ได้ แต่ใบเสร็จหลังลงคะแนน **ห้ามมีเลขลำดับของผู้ใช้** และเวลาแสดงได้แค่ช่วงชั่วโมง (กฎข้อ 11)
- **Gumroad** — สติกเกอร์ "ฉันไปใช้สิทธิ์แล้ว" เป็น SVG มีปุ่มบันทึกภาพ (SVG → PNG ผ่าน canvas) ไม่ทำระบบแชร์ ถ้าเกิน 2 ชั่วโมงให้ตัดปุ่มบันทึก เหลือแค่สติกเกอร์
- **Blossom** — เครื่องเขียนร่วมสมัยกับตราครั่งแบบเบา ๆ ไม่ใช่เว็บจดหมายโบราณ
- **Studio Dark** — ก่อนประกาศผล ไฟเวทีเป็นกลาง ทุกพรรคได้แสงเท่ากัน สปอตไลท์ส่องผู้ชนะเฉพาะหลังเปิดผล (กฎข้อ 7)
- **Original** — เป็น template ความคุ้นเคย เก็บโครงเดิม ไม่สร้างโลกใหม่

**fms-official** ยังไม่ลบ เงื่อนไขอยู่ในกฎกลาง

**commit:** fixes → ballot-official → docs (เสร็จแล้ว) จากนั้นโครงสร้างกลางเป็น commit แยก แล้วจึง Verdure

**Phase 0 — โครงสร้างกลาง:**
- `resolveTemplatePage(templateId, page)` ให้ทุก route ถามก่อน (v2 เท่านั้น v1 ไม่แตะ) แทนการเสียบ v2 ในกิ่งของ fms-official
- แยกพฤติกรรมเนื้อหาพรรคแบบไม่มีหน้าตาไว้ส่วนกลาง: การเรียงทีม, กติกาแกลเลอรี/ช่องทางติดต่อ, dialog, ตัวดูภาพ
- ย้ายโค้ดไปไว้ใน `v2/templates/<slug>/` ตามโครงที่ตกลงกัน
- ballot-official ต้องหน้าตาเหมือนเดิมทุกพิกเซล ตรวจด้วยการเทียบภาพหน้าจอก่อนและหลัง
