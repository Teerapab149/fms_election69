# กฎกลางของ v2 templates

ตกลงกับเจ้าของโปรเจกต์ 29 ก.ย. 2569 ใช้กับทุก template ใน `components/v2/`
**ballot-official คือต้นแบบอ้างอิง (golden reference)** — ถ้าสงสัยว่ากฎข้อไหนหมายถึงอะไร ให้ดูว่า ballot-official ทำอย่างไร

## การออกแบบ

1. **One page, one visual protagonist.** ทุกหน้ามีตัวเอกทางภาพชิ้นเดียว ที่เหลือทำหน้าที่สนับสนุน
2. **ทุก template มีวัตถุหนึ่งชิ้นที่เปลี่ยนสถานะไปตามเส้นทางการเลือกตั้ง** ไม่ใช่วัตถุใหญ่วางทุกหน้า แต่เป็นชิ้นเดียวกันในสถานะต่างกัน
   ballot-official: บัตรตัวอย่าง → บัตรที่กำลังกรอก → บัตรที่พับส่งเข้าหีบ → ต้นขั้ว → หีบปิดผนึก → ใบรายงานผล
3. **พฤติกรรมและข้อมูลอยู่ส่วนกลาง หน้าตาเป็นของแต่ละ template**
4. **ห้ามเขียนข้อความที่ admin แก้ได้ลงในโค้ด** — ข้อเท็จจริงของการเลือกตั้งมาจากตั้งค่าทั่วไป (globalConfig) ข้อความของหน้าผ่าน element id พร้อมค่าตั้งต้นในไฟล์ `builtIn/<slug>.js`
5. **ภาษาไทยก่อน** เว้นแต่แนวคิดของ template ต้องใช้ภาษาอื่นจริง ๆ
6. **สถานะการเลือกตั้งมาจากแหล่งเดียว** — `useElectionStatus` เท่านั้น ห้ามมี `if (date < …)` ใน template
7. **ห้ามให้ภาพเผยผลคะแนนก่อนประกาศอย่างเป็นทางการ** — ก่อนเปิดผล ทุกพรรคต้องได้การแสดงผลเท่ากัน (เรียงตามเบอร์ แสงเท่ากัน ขนาดเท่ากัน)
8. **มือถือเป็นการจัดวางชั้นหนึ่ง** ไม่ใช่หน้าจอคอมที่ถูกบีบ
9. **ของตกแต่งต้องสนับสนุนแนวคิด** อะไรที่แย่งสายตาจากตัวเอกให้ตัดทิ้ง
10. **template ต้องจำได้จากวัตถุหรือแนวคิด ไม่ใช่จากสี** — เปลี่ยนสีแล้วต้องยังรู้ว่าเป็นตัวไหน
11. **ห้ามแสดงอะไรที่ระบุลำดับหรือเวลาที่ผู้ใช้ลงคะแนน ละเอียดกว่าที่ระบบเก็บไว้กับบัตร** — ตาราง `Ballot` มี `seq` เรียงต่อกันและ `hourBucket` ระดับชั่วโมง ดังนั้นห้ามมี "คุณคือคนที่ N" หลังลงคะแนน และเวลาแสดงได้แค่ช่วงชั่วโมง

## โครงสร้างโค้ด

- **แยกพฤติกรรมก่อน ค่อยแยกหน้าตา** — primitives เป็นแบบไม่มีหน้าตา (dialog, ตัวดูภาพ, การเรียงทีม, กติกาแสดงแกลเลอรี/ช่องทางติดต่อ) ส่วนบัตรหรือการ์ดพรรคอยู่ใน template ของตัวเอง จนกว่าจะเห็นซ้ำจริงอย่างน้อย 3 ตัว
- **route ไม่รู้จัก template** — ทุกหน้าถาม `resolveTemplatePage(templateId, page)` ก่อน ได้ component ของ v2 ก็ render ไม่ได้ก็ใช้ dispatch ของ v1 ตามเดิม ห้ามเพิ่ม `if` ต่อ template ใน route
- **v1 ไม่ถูกแตะ** จนกว่าจะลบ template เดิม
- **fms-official ยังไม่ลบ** จน v2 ผ่านครบทุกหน้า ผ่าน routing ผ่านข้อมูลจริง ผ่านมือถือ ไม่มี regression และผ่าน deploy preview

## โครงไฟล์ (หลัง foundation commit)

```
src/components/v2/
├── families.js         slug → base family + หน้าที่สร้างแล้ว (อ่านได้ฝั่ง server)
├── registry.js         component ของแต่ละ template
├── resolve.js          resolveTemplatePage(id, page), familyFor(id, v2Page) — route ถามที่นี่ที่เดียว
├── shared/             พฤติกรรมและข้อมูล ไม่มีหน้าตา
│   ├── election/voteTime.mjs       hourWindow() — กฎข้อ 11
│   ├── results/resultsView.mjs     ลำดับแถว สัดส่วน turnout — กฎข้อ 7 (ก่อนประกาศไม่มีคะแนนในแถว)
│   ├── party/partyContent.mjs      ปก แกลเลอรี ส่วนที่ว่าง ลำดับทีม
│   ├── party/usePartyContent.js    hook ที่ต่อกับ utils ของแอป
│   └── interaction/useDialog.js    Escape, focus, หยุด scroll
└── templates/<slug>/   หน้าตาของแต่ละ template
```

**เพิ่ม template ใหม่:** สร้าง `templates/<slug>/` + `builtIn/<slug>.js` → ใส่ใน `families.js` (base + built) และ `registry.js` → ลงทะเบียนใน `templates/index.js` และ `FAMILY_CATEGORY` — route และ template-preview ไม่ต้องแก้
เทสต์: `node --test scripts/smoke/v2Shared.test.mjs scripts/smoke/electionStatus.test.mjs`

## วิธีทำงาน

- commit แยกเป็นชุดที่อ่านย้อนได้: โครงสร้างกลางไม่ปนกับ template ใหม่ ไม่ปนกับการแก้บั๊ก
- **commit โครงสร้างกลางต้องไม่เปลี่ยนหน้าตาของ ballot-official** เว้นแต่เป็นบั๊กที่เจอจากการตรวจ
- ใช้ milestone ไม่ใช่จำนวนวันต่อตัว: ถ้า Verdure ใช้เกินหนึ่งวัน คือสัญญาณให้ตรวจโครงสร้าง ไม่ใช่ให้รีบ
