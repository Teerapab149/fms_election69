# อัปเดตเครื่องจริงเป็นรุ่น พ.ย. 2569

สำหรับเจ้าหน้าที่ IT ของคณะ หน้านี้มีทุกอย่างที่ต้องทำเพื่ออัปเดตระบบเลือกตั้ง OVS บนเครื่องจริง
คำสั่งทุกบล็อกก๊อปวางได้เลย ส่วนที่ 1 ทำวันนี้ ส่วนที่ 2 และ 3 ทำก่อนวันเลือกตั้ง

หน้านี้เขียนสำหรับ **เครื่องที่ไม่ใช้ Docker** (เว็บรันด้วย `node`, pm2 หรือ systemd)
ถ้าเครื่องใช้ Docker ให้ทำตาม [คู่มือ IT หัวข้อ 6.2](STAFF-IT-GUIDE.md#update) แทนส่วนที่ 1

ถ้าคำสั่งไหนขึ้น error ให้หยุดตรงนั้น แล้วส่งข้อความ error ให้ผู้พัฒนา ไม่ต้องลองแก้เอง

---

## ส่วนที่ 1 อัปเดตเครื่องจริง

ใช้เวลาประมาณ 20 นาที เว็บจะดับในขั้นที่ 3 ถึง 5

**ก่อนเริ่ม**

- สำรองฐานข้อมูลหนึ่งรอบด้วยวิธีที่ใช้อยู่
- รันทุกคำสั่งในโฟลเดอร์โปรเจกต์ (เช่น `/opt/fms-election`) ด้วย **ผู้ใช้เดียวกับที่ใช้เปิดเว็บ**
- จดรุ่นเดิมไว้ เผื่อต้องย้อนกลับ:

```bash
git rev-parse HEAD
```

### ขั้นที่ 1 ตั้งที่เก็บรูปให้อยู่นอกโฟลเดอร์โปรแกรม (ทำครั้งเดียว)

ถ้าไม่ทำ รูปที่กรรมการอัปโหลดจะหายทุกครั้งที่อัปเดต เพราะขั้น build ลบโฟลเดอร์เดิมทิ้ง

```bash
sudo mkdir -p /var/lib/fms-ovs/images
sudo chown -R $(id -un):$(id -gn) /var/lib/fms-ovs/images
cp -a public/images/. /var/lib/fms-ovs/images/
cp -a .next/standalone/public/images/. /var/lib/fms-ovs/images/
```

สองบรรทัดหลังย้ายรูปเดิมตามไป ถ้าบรรทัดไหนขึ้นว่าไม่พบโฟลเดอร์ ข้ามได้

แล้วเพิ่มบรรทัดนี้ในไฟล์ `.env` (ถ้ามีบรรทัด `UPLOAD_ROOT` อยู่แล้ว ไม่ต้องทำขั้นนี้):

```
UPLOAD_ROOT=/var/lib/fms-ovs/images
```

### ขั้นที่ 2 ให้ nginx รับไฟล์รูปขนาดใหญ่ได้ (ทำครั้งเดียว)

ค่าเริ่มต้นของ nginx รับได้แค่ 1 MB รูปที่ใหญ่กว่านั้นจะอัปโหลดไม่ผ่าน
เพิ่มบรรทัดนี้ในบล็อก `server` ของเว็บนี้:

```nginx
client_max_body_size 200m;
```

แล้วตรวจและ reload:

```bash
sudo nginx -t
sudo systemctl reload nginx
```

### ขั้นที่ 3 หยุดเว็บ

ใช้คำสั่งตามวิธีที่เปิดเว็บอยู่ อย่างใดอย่างหนึ่ง:

```bash
pm2 stop fms-ovs
```

```bash
sudo systemctl stop fms-ovs
```

### ขั้นที่ 4 อัปเดตโค้ดและสร้างโปรแกรมใหม่

```bash
git pull --ff-only
npm ci
npx prisma generate
DATABASE_URL="$MAINT_DATABASE_URL" npx prisma migrate deploy
npm run build
mkdir -p .next/standalone/.next
cp -a .next/static .next/standalone/.next/
cp -a public .next/standalone/
ln -sf "$PWD/.env" .next/standalone/.env
```

- `git pull` ไม่ต้องล็อกอินหรือขอสิทธิ์
- `$MAINT_DATABASE_URL` คือ URL ของบัญชีฐานข้อมูลที่เป็นเจ้าของตาราง (`fms_migrate`) ถ้ายังไม่ได้ตั้งใน terminal นี้ ดูวิธีตั้งใน [คู่มือ IT หัวข้อ 3.2](STAFF-IT-GUIDE.md#first-install)
- บรรทัด `migrate` ถ้าขึ้น `No pending migrations to apply` คือปกติ
- `npm run build` ไม่ต้องต่อเน็ตไป Google แล้ว (รุ่นก่อนเคยล้มแบบสุ่มเพราะเรื่องนี้)

### ขั้นที่ 5 เปิดเว็บ

```bash
pm2 restart fms-ovs --update-env
```

```bash
sudo systemctl start fms-ovs
```

### ขั้นที่ 6 ตรวจ

```bash
curl -i http://localhost:3000/api/health
```

ต้องได้ `200` และ `{"ok":true,"db":true}`

แล้วเข้าหน้าแอดมิน เมนู **ความพร้อมและระบบ** กด **ตรวจซ้ำ** และ **แคปหน้าจอส่งผู้พัฒนา**

- ข้อ "โฟลเดอร์เก็บรูปที่อัปโหลด" ต้องขึ้นเขียว ถ้าแดง แปลว่าผู้ใช้ที่เปิดเว็บเขียนโฟลเดอร์ `/var/lib/fms-ovs/images` ไม่ได้
- เมื่อข้อนี้เขียว กรรมการอัปโหลดรูปและกรอกข้อมูลพรรคจากหน้าแอดมินได้เลย ไม่ต้องทำอะไรบนเครื่องเพิ่ม
- หลังอัปเดต แอดมินทุกคนต้องล็อกอินใหม่หนึ่งครั้ง

**ถ้าต้องย้อนกลับ** ดู [คู่มือ IT หัวข้อ 6.2.2](STAFF-IT-GUIDE.md#update-no-docker)

## ส่วนที่ 2 งานก่อนวันเลือกตั้ง

ไม่ต้องทำวันเดียวกับส่วนที่ 1

### 1. นำเข้ารายชื่อนักศึกษาผู้มีสิทธิ์

ทำเมื่อปีนี้ยังไม่ได้นำเข้า ใช้ไฟล์ `.xlsx` หรือ `.csv` จากทะเบียน
**คำสั่งนี้เขียนฐานข้อมูลทันที ไม่มีขั้นยืนยัน** ตรวจไฟล์ก่อนรัน หัวคอลัมน์ที่ต้องมีอยู่ใน [คู่มือ IT หัวข้อ 4.2](STAFF-IT-GUIDE.md#operations)

```bash
DATABASE_URL="$APP_DATABASE_URL" npm run import-students -- /path/ไฟล์รายชื่อ.xlsx
```

### 2. ตั้งรหัสเข้าหน้าแอดมินให้กรรมการทีละคน

รุ่นนี้กรรมการแต่ละคนมีรหัสของตัวเอง ไม่ใช้รหัสกลางร่วมกัน เพื่อให้บันทึกการใช้งานบอกได้ว่าใครทำอะไร
ผู้พัฒนาจะส่งรายชื่อรหัสนักศึกษาของกรรมการให้ **ห้ามทำระหว่างเปิดหีบ** เพราะคนที่เข้าระบบค้างไว้จะถูกออกทันที

```bash
DATABASE_URL="$APP_DATABASE_URL" node scripts/admin.js --set-password <รหัส นศ. ของกรรมการ>
```

รันทีละคน รหัสแสดงบนจอครั้งเดียว ส่งให้เจ้าตัวโดยตรง เมื่อทุกคนเข้าได้แล้ว ปิดรหัสกลาง:

```bash
DATABASE_URL="$APP_DATABASE_URL" node scripts/admin.js --disable-shared
DATABASE_URL="$APP_DATABASE_URL" node scripts/admin.js --list
```

รายละเอียดอยู่ใน [คู่มือ IT หัวข้อ 4.1](STAFF-IT-GUIDE.md#operations)

### 3. สำรองข้อมูลอัตโนมัติ และเก็บสำเนาไว้เครื่องอื่น

เครื่องที่ไม่ใช้ Docker ต้องตั้งเอง รวมถึงการเก็บปลายโซ่บัตรไว้นอกเครื่องช่วงเปิดหีบ
ทำตาม [เช็คลิสต์หัวข้อ 12](DEPLOY-CHECKLIST-2026.md#12-สำรองข้อมูลและสำเนานอกเครื่อง)

### 4. ซ้อมระบบ แล้วล้างข้อมูลซ้อม

ทำตาม [เช็คลิสต์หัวข้อ 13](DEPLOY-CHECKLIST-2026.md#13-ซ้อมระบบแล้วล้างบัตรซ้อม) มีสองเรื่องที่ต้องรู้ก่อนซ้อม:

- เมื่อมีบัตรใบแรก (รวมบัตรซ้อม) จะแก้ชื่อพรรคและหมายเลขไม่ได้ จนกว่าจะล้างบัตร
- ถ้าซ้อมจนกดประกาศผล หีบจะเปิดอีกไม่ได้ จนกว่าจะล้างข้อมูลซ้อม

## ส่วนที่ 3 สิ่งที่เปลี่ยนในวันปิดหีบ

ตอนรับรองผล ระบบบังคับให้กรอกคะแนนของทุกตัวเลือกจากการนับซ้ำด้วยกุญแจส่วนตัว
ถ้าตัวเลขไม่ตรงกับในระบบแม้ตัวเดียว ระบบจะไม่รับรอง จึงต้องนัดผู้ถือกุญแจและเจ้าหน้าที่ผู้รับรองไว้ล่วงหน้า

ขั้นตอนทั้งหมดอยู่ใน [คู่มือ IT หัวข้อ 4.3](STAFF-IT-GUIDE.md#operations) และ [เช็คลิสต์หัวข้อ 15](DEPLOY-CHECKLIST-2026.md#15-หลังปิดหีบ) ควรอ่านก่อนวันจริงหนึ่งรอบ
และเก็บ log ของ nginx วันเลือกตั้งไว้ อย่าให้ถูกหมุนทิ้ง เพราะใช้ตรวจตอนรับรองผล
