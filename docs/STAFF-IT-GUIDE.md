# คู่มือเจ้าหน้าที่ IT — ระบบเลือกตั้งออนไลน์ FMS

สำหรับ **เจ้าหน้าที่ IT ของคณะ** ที่ดูแลเซิร์ฟเวอร์และฐานข้อมูล
ไฟล์เดียวจบ ทุกคำสั่งคัดลอกไปวางได้เลย รันบนเครื่องเซิร์ฟเวอร์ในโฟลเดอร์โปรเจกต์

> **แบ่งหน้าที่กันแบบนี้**
>
> | งาน | ใคร |
> |---|---|
> | เซิร์ฟเวอร์ · ฐานข้อมูล · การติดตั้ง · อัปเดตโค้ด · สำรองข้อมูล · ล้างข้อมูลปีเก่า · บัญชีแอดมิน | **คุณ (IT คณะ)** |
> | ข้อมูลการเลือกตั้ง · พรรค · วันเวลา · ธีม · เปิด-ปิดหีบ · ประกาศผล | **สโมสรนักศึกษา** (คู่มือของเขา: `docs/ADMIN-GUIDE.md`) |
> | เก็บ private key ของบัตรลงคะแนน | **คุณ + อาจารย์ที่ปรึกษา** คนละครึ่ง |
>
> สโมสรฯ เป็นนักศึกษา ไม่มีสิทธิ์เข้าเซิร์ฟเวอร์ และหน้าแอดมินก็ไม่มีปุ่มที่ทำงานหลังบ้าน
> โดยตั้งใจ เขาจะติดต่อมาขอตามรายการใน [§4](#4-งานที่สโมสรฯ-จะขอมา)

|---|---|
| ติดตั้งครั้งแรก / เว็บล่มอยากให้กลับมา | [§1 คำสั่งเดียวจบ](#1-คำสั่งเดียวจบ) |
| รายการคำสั่งทั้งหมด | [§2 ตารางคำสั่ง](#2-ตารางคำสั่ง) |
| ตั้งค่าเซิร์ฟเวอร์ครั้งแรกแบบละเอียด | [§3 ติดตั้งครั้งแรก](#3-ติดตั้งครั้งแรก-ทำครั้งเดียว) |
| สโมสรฯ ขออะไรมา ต้องทำยังไง | [§4 งานที่สโมสรฯ จะขอมา](#4-งานที่สโมสรฯ-จะขอมา) |
| ล้างข้อมูลขึ้นปีใหม่ | [§5 ขึ้นปีใหม่](#5-ขึ้นปีใหม่) |
| มีโค้ดใหม่ต้องอัปเดต | [§6 อัปเดตโค้ด](#6-อัปเดตโค้ด) |

## 1. คำสั่งเดียวจบ

```bash
sh scripts/setup.sh
```

ตรวจเครื่องมือ → ตรวจ `.env` → ติดตั้ง dependency → สร้างตารางฐานข้อมูล → ล็อกสิทธิ์ตารางบัตร
→ เปิดระบบด้วย docker → ตรวจว่าเว็บตอบจริง → แสดงรายชื่อแอดมิน

หยุดทันทีที่เจอปัญหาและบอกวิธีแก้ · รันซ้ำได้ ไม่ลบข้อมูล

```bash
sh scripts/setup.sh --check              # ตรวจอย่างเดียว ไม่แก้อะไรเลย
sh scripts/setup.sh --admin 6610510149   # ติดตั้ง + ตั้งแอดมินคนแรก
```

ไม่ทำให้ 3 อย่าง เพราะต้องมีคนตัดสินใจ: พิธีสร้างกุญแจบัตร ([§3.3](#33-พิธีสร้างกุญแจบัตร-ปีละครั้ง-10-นาที)) ·
นำเข้ารายชื่อนักศึกษา (ต้องมีไฟล์จากสโมสรฯ) · ลบข้อมูล ([§5](#5-ขึ้นปีใหม่))

## 2. ตารางคำสั่ง

### ต้องทำ

| คำสั่ง | ใช้ตอนไหน |
|---|---|
| `sh scripts/setup.sh` | ติดตั้งครั้งแรก · หลังอัปเดตโค้ด · เว็บล่มอยากให้กลับมา |
| `sh scripts/backup.sh` | **ก่อนลบหรืออัปเดตทุกครั้ง** |
| `node scripts/admin.js --grant <รหัส นศ.>` | สโมสรฯ ขอเพิ่มกรรมการเป็นแอดมิน |
| `node scripts/admin.js --revoke <รหัส นศ.>` | ถอดสิทธิ์คนพ้นวาระ |
| `node scripts/admin.js --rotate-password` | ออกรหัสกลางใหม่ (ส่งมอบชุดใหม่ / รหัสหลุด / ลืม) |
| `npm run import-students -- <ไฟล์รายชื่อ>` | นำเข้าผู้มีสิทธิ์เลือกตั้งปีนั้น |
| `node scripts/generate-election-keys.js` | พิธีสร้างกุญแจบัตร ปีละครั้ง |
| `npm run preflight` | ตรวจความพร้อมก่อนเปิดหีบ |
| `node scripts/reconcile-scores.js` | ตรวจคะแนนหลังปิดหีบ ก่อนให้สโมสรฯ ประกาศผล |

### ควรรู้ ใช้เมื่อจำเป็น

| คำสั่ง | ใช้ตอนไหน |
|---|---|
| `sh scripts/setup.sh --check` | อยากรู้สถานะโดยไม่แก้อะไร |
| `node scripts/admin.js --list` | ใครเป็นแอดมินบ้าง รหัสกลางตั้งหรือยัง |
| `node scripts/admin.js --break-glass` | กรรมการล็อกอินไม่ได้ทั้งทีม ต้องการบัญชีสำรอง |
| `node scripts/verify-ballot-chain.js` | มีคนตั้งคำถามกับผล — พิสูจน์ว่าบัตรไม่ถูกแก้ |
| `npm run archive-year` | เก็บผลปีเก่าก่อนล้างข้อมูล |
| `docker compose logs --tail 100 web` | ดู log ตอนมีปัญหา |
| `docker compose restart web` | เว็บค้าง อยากรีสตาร์ทโดยไม่ build ใหม่ |
| `psql "<fms_migrate>" -f scripts/sql/annual-reset.sql` | ล้างข้อมูลขึ้นปีใหม่ ([§5](#5-ขึ้นปีใหม่)) |

### ห้ามลืม

- **สำรองข้อมูลก่อนลบหรืออัปเดตเสมอ**
- **ปิดหีบเสร็จ ถอดแอดมินชุดเก่าและเปลี่ยนรหัสกลาง** ([§4](#4-งานที่สโมสรฯ-จะขอมา))
- **กระดาษ private key ห้ามอยู่บนเซิร์ฟเวอร์** ([§3.3](#33-พิธีสร้างกุญแจบัตร-ปีละครั้ง-10-นาที))
- **ห้ามอัปเดตโค้ดระหว่างการโหวตกำลังเปิด**

## 3. ติดตั้งครั้งแรก (ทำครั้งเดียว)

### 3.1 ของที่ต้องมีก่อน

- เครื่อง Linux ที่มี Docker และ Docker Compose
- PostgreSQL — สร้างเองหรือให้ docker สร้างก็ได้ รายละเอียดสิทธิ์ที่ต้องการอยู่ใน [§3.5](#35-ทำไมต้องมีบัญชีฐานข้อมูล-2-ตัว)
- ค่า PSU SSO ปีนั้น (client id / client secret / redirect uri) จาก IT ม.อ.
- ไฟล์รายชื่อนักศึกษาผู้มีสิทธิ์ จากสโมสรฯ

### 3.2 ตั้งค่า `.env`

สร้างไฟล์ `.env` ในโฟลเดอร์โปรเจกต์:

```
DATABASE_URL=              # ของบัญชี fms_app (บัญชีที่เว็บใช้)
MIGRATE_DATABASE_URL=      # ของบัญชี fms_migrate (ใช้ตอนสร้าง/แก้ตารางเท่านั้น)
NEXTAUTH_SECRET=           # สุ่มด้วย: openssl rand -base64 32
NEXTAUTH_URL=              # URL จริง เช่น https://xxx.psu.ac.th/fms-ovs
NEXT_PUBLIC_BASE_PATH=/fms-ovs
BASE_PATH=/fms-ovs
ADMIN_JWT_SECRET=          # สุ่มด้วย: openssl rand -hex 32
AUTHENTIK_CLIENT_ID=
AUTHENTIK_CLIENT_SECRET=
AUTHENTIK_REDIRECT_URI=
ELECTION_BALLOT_PUBLIC_KEY=   # ได้จาก §3.3
BALLOT_CHAIN_SECRET=          # ได้จาก §3.3
POSTGRES_PASSWORD=            # เฉพาะกรณีให้ docker สร้างฐานข้อมูลให้เอง
```

**รหัสผ่านแอดมินไม่อยู่ในไฟล์นี้** อยู่ในฐานข้อมูลเป็น bcrypt hash ตั้งด้วยคำสั่งใน [§4](#4-งานที่สโมสรฯ-จะขอมา)

### 3.3 พิธีสร้างกุญแจบัตร (ปีละครั้ง ~10 นาที)

ทำร่วมกับ **อาจารย์ที่ปรึกษา** และตัวแทนสโมสรฯ บนเครื่องที่ไว้ใจได้:

```bash
node scripts/generate-election-keys.js
```

- **public key + chain secret** → วางใน `.env` บนเซิร์ฟเวอร์
- **private key** → เก็บออฟไลน์ (กระดาษ/USB) แบ่งกันถือระหว่างคุณกับอาจารย์ที่ปรึกษา
  **ห้ามอยู่บนเซิร์ฟเวอร์เด็ดขาด** ใช้เฉพาะกรณีมีข้อพิพาทแล้วต้องนับคะแนนใหม่ต่อหน้ากรรมการ
  ถ้าหาย ผลเลือกตั้งไม่เสีย เสียแค่ความสามารถนับใหม่

> ⚠️ **ห้ามใช้กุญแจของเครื่องทดสอบบนเครื่องจริง** และเปลี่ยนกุญแจได้ก่อนบัตรใบแรกลงกล่อง
> เท่านั้น — เปลี่ยนทีหลังบัตรเก่าจะเปิดด้วยกุญแจใหม่ไม่ได้
>
> ถ้ากุญแจสองตัวใน `.env` ไม่ครบ ระบบจะปิดรับโหวตทันที แทนที่จะเก็บบัตรแบบไม่เข้ารหัส

### 3.4 ติดตั้งและเปิดระบบ

```bash
sh scripts/setup.sh --admin <รหัส นศ. ของประธานสโมสรฯ>
node scripts/admin.js --rotate-password    # ได้รหัสกลาง ส่งให้สโมสรฯ
npm run import-students -- <ไฟล์รายชื่อ>
```

จากนั้นบอกสโมสรฯ ให้เข้าไปตั้งค่าการเลือกตั้งและกดปุ่ม "ตรวจความพร้อมระบบ" เอง

### 3.5 ทำไมต้องมีบัญชีฐานข้อมูล 2 ตัว

ไม่ใช่ database 2 อัน — ข้อมูลชุดเดียวกัน แต่เข้าถึงด้วยสิทธิ์คนละระดับ

| บัญชี | ใช้ตอนไหน | สิทธิ์ |
|---|---|---|
| `fms_migrate` | เฉพาะตอนสร้าง/แก้โครงสร้างตาราง | เต็ม |
| `fms_app` | ตัวเว็บใช้ตลอดเวลาที่รันอยู่ | จำกัด — **เพิ่มบัตรได้ แก้/ลบบัตรไม่ได้** |

สร้างครั้งเดียวตอนติดตั้ง (คำสั่งอยู่ในหัวไฟล์ `scripts/sql/ballot-grants.sql`) แล้ว `setup.sh`
จะรันไฟล์นั้นให้เอง เพื่อบังคับสิทธิ์ตามตาราง

นี่คือกลไกที่ทำให้พูดได้ว่า **ผลเลือกตั้งที่ลงไปแล้วแก้ไม่ได้ แม้แต่คนดูแลระบบเอง** — ถ้าเว็บ
ต่อฐานข้อมูลด้วยบัญชีสิทธิ์เต็ม ข้อจำกัดนี้ไม่มีความหมายเลย

## 4. งานที่สโมสรฯ จะขอมา

| เขาขอว่า | คุณรัน | หมายเหตุ |
|---|---|---|
| เพิ่มกรรมการเป็นแอดมิน | `node scripts/admin.js --grant <รหัส นศ.>` | ถ้าขึ้น "ไม่พบ" ให้เขาล็อกอินหน้าเว็บด้วย PSU Passport หนึ่งครั้งก่อน แล้วรันซ้ำ · ไม่ต้องออกรหัสใหม่ รหัสกลางเดิมใช้ได้เลย |
| ถอดสิทธิ์คนพ้นวาระ | `node scripts/admin.js --revoke <รหัส นศ.>` | มีผลกับคลิกถัดไปทันที · **ถ้าเขารู้รหัสกลาง ให้เปลี่ยนรหัสด้วย** |
| ลืมรหัสกลาง / รหัสหลุด | `node scripts/admin.js --rotate-password` | รหัสขึ้นจอครั้งเดียว · **รหัสเดิมตายทันที** ทุกคนต้องได้รหัสใหม่ → แจ้งเขาก่อนกด |
| นำเข้ารายชื่อผู้มีสิทธิ์ | `npm run import-students -- <ไฟล์>` | |
| ล้างข้อมูลปีเก่า / คะแนนซ้อม | [§5](#5-ขึ้นปีใหม่) | สำรองก่อนเสมอ |
| ตรวจคะแนนก่อนประกาศผล | `node scripts/reconcile-scores.js` | ตอบเขาว่าตรงกันทั้งสามทางหรือไม่ ก่อนเขากดเผยแพร่ผล |
| มีคนตั้งคำถามกับผล | `node scripts/verify-ballot-chain.js` | ถ้าถึงขั้นนับใหม่ ต้องใช้ private key กับอาจารย์ที่ปรึกษา |
| ปุ่มตรวจความพร้อมขึ้นแดง | `npm run preflight` | เห็นสาเหตุฝั่งเซิร์ฟเวอร์ชัดกว่าหน้าเว็บ |

**เรื่องรหัสกลาง** — เป็นรหัสตัวเดียวที่กรรมการทั้งชุดใช้ร่วมกัน แต่ระบบยังรู้ว่าใครกดอะไร
เพราะตัวตนมาจากรหัส นศ. ที่ล็อกอิน · รหัสกลางอย่างเดียวเปิดอะไรไม่ได้ ต้องเป็นคนที่ถูก
`--grant` ไว้ด้วย · ในฐานข้อมูลเก็บแค่ bcrypt hash เปิดดูย้อนหลังไม่ได้

**ส่งรหัสให้เขายังไง** — ส่งตัวต่อตัวหรือช่องทางที่ปิด แล้วให้เก็บลงตัวจัดการรหัสผ่าน
ห้ามพิมพ์ลงเอกสาร ไฟล์ในโปรเจกต์ หรือแชทกลุ่มที่ค้างนาน ๆ

## 5. ขึ้นปีใหม่

หน้าเว็บไม่มีปุ่มลบข้อมูล ตั้งใจให้เป็นแบบนั้น (ดูเหตุผล [§3.5](#35-ทำไมต้องมีบัญชีฐานข้อมูล-2-ตัว))

```bash
# 1. สำรองก่อน — ลบแล้วกู้ไม่ได้
sh scripts/backup.sh

# 2. เก็บผลปีเก่าไว้อ้างอิง
npm run archive-year

# 3. ล้าง (ใช้บัญชี fms_migrate ไม่ใช่ของเว็บ)
psql "<connection string ของ fms_migrate>" -f scripts/sql/annual-reset.sql

# 4. ยืนยันว่าเป็นศูนย์จริง
npm run preflight
```

ค่าเริ่มต้นคือล้างคะแนน บัตร และคืนสิทธิ์โหวต **แต่เก็บรายชื่อพรรคไว้**
ถ้าสโมสรฯ ขอให้ลบพรรคชุดเก่าด้วย ให้เปิดคอมเมนต์สามบรรทัดท้ายไฟล์ตามที่เขียนไว้ในนั้น

> เก็บไฟล์ backup ของปีเก่าไว้อย่างน้อยหนึ่งปี — บัตรที่ลบแล้วนับใหม่ไม่ได้อีกเลย

## 6. อัปเดตโค้ด

```bash
sh scripts/backup.sh          # 1. สำรองก่อนเสมอ
git pull                      # 2. ดึงโค้ดใหม่
sh scripts/setup.sh           # 3. ที่เหลือสคริปต์จัดการให้ (migrate + build + เปิดใหม่)
```

เช็คหลังอัปเดต: หน้าแรกขึ้นปกติ · ล็อกอินแอดมินได้ · หน้าผลคะแนนไม่พัง

**ห้ามอัปเดตระหว่างการโหวตกำลังเปิด** ถ้าจำเป็นจริง ๆ ให้สโมสรฯ สลับโหมดเป็น `PAUSE` ก่อน

ถ้าอัปเดตแล้วพัง:

```bash
git checkout <commit เดิม>
sh scripts/setup.sh
```

ฐานข้อมูลไม่ถูกแตะจากการ build จึงกลับรุ่นเดิมได้ทันที (ยกเว้นรอบที่มีการแก้โครงสร้าง
ฐานข้อมูล — กรณีนั้นต้องกู้จาก backup ข้อ 1)

| เว็บค้าง ช้าผิดปกติ | `docker compose restart web` |
| แอดมินล็อกอินไม่ได้ | `node scripts/admin.js --list` — มีชื่อไหม รหัสกลางตั้งหรือยัง |
| นักศึกษาล็อกอินไม่ได้ทั้งระบบ | PSU SSO ฝั่งมหาวิทยาลัย — ติดต่อ IT ม.อ. ขอค่าใหม่ แล้วอัปเดต `.env` |
| โหวตไม่ได้ ทั้งที่ยังไม่ถึงเวลาปิด | กุญแจบัตรใน `.env` ไม่ครบ → `sh scripts/setup.sh --check` |
| คะแนนดูไม่ตรง | `node scripts/reconcile-scores.js` |
| รูปหายหลัง deploy | ตรวจ volume `./public/images` ใน `docker-compose.yml` |

เก็บสามอย่างนี้ไว้เสมอเวลาต้องส่งต่อให้ทีมพัฒนา: เกิดตอนไหน · ข้อความ error เต็มบรรทัด ·
`docker compose logs --tail 100 web`

**ระบบล่มระหว่างเปิดหีบ** — ให้สโมสรฯ สลับโหมดเป็น `PAUSE` ก่อนเป็นอันดับแรก บัตรที่ลงไปแล้ว
ปลอดภัย ไม่หาย ไม่ซ้ำ แล้วค่อยหาสาเหตุ

## ภาคผนวก — ใบขอ database (ถ้าต้องขอจากหน่วยงานอื่น)

> **สิ่งที่ขอ**
>
> 1. **PostgreSQL 1 database** ชื่อแนะนำ `fms_election` (ระบบใช้ Prisma ORM มาตรฐาน
>    ไม่มี extension พิเศษ)
> 2. **role 2 ตัว** — `fms_migrate` (เจ้าของ schema ใช้ตอนติดตั้ง/อัปเดตโครงสร้าง) และ
>    `fms_app` (ตัวเว็บใช้จริง สิทธิ์จำกัด: เพิ่มบัตรได้ แก้/ลบบัตรไม่ได้)
> 3. **connection string ของทั้ง 2 role** ส่งผ่านช่องทางปลอดภัย
> 4. **Timezone** ของเครื่อง/container ตั้ง `Asia/Bangkok`
> 5. **Backup รายวันตามมาตรฐาน** — บัตรลงคะแนนถูกเข้ารหัสและไม่ผูกกับตัวผู้โหวตตั้งแต่ชั้น
>    โครงสร้าง (ใน backup ก็ไม่มีข้อมูลว่าใครเลือกใคร)
>
> **ไม่ต้องทำ:** restore ข้อมูลปีก่อน · เปิด public access (แอปกับ DB คุยกันภายใน) ·
> ติดตั้งอะไรใน DB (migration รันเองด้วย `fms_migrate`)
