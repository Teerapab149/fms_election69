## 1. คำสั่งเดียวจบ

```bash
sh scripts/setup.sh
```

ตรวจเครื่องมือ → ตรวจ `.env` → ติดตั้ง dependency → สร้างตารางฐานข้อมูล → ล็อกสิทธิ์ตารางบัตร
→ เปิดระบบด้วย docker → ตรวจว่าเว็บตอบจริง → แสดงรายชื่อแอดมิน

หยุดทันทีที่เจอปัญหาและบอกวิธีแก้ · รันซ้ำได้ ไม่ลบข้อมูล

```bash
sh scripts/setup.sh --check              # ตรวจอย่างเดียว ไม่แก้อะไรเลย
sh scripts/setup.sh --admin 6610510149   # ติดตั้ง + ตั้งแอดมินคนแรก
sh scripts/setup.sh --compose docker-compose.local.yml   # ใช้ compose ไฟล์อื่น
```

**ข้อที่ 6 คือข้อที่สำคัญที่สุด** — สคริปต์ไม่ได้ดูแค่ว่าหน้าแรกขึ้น แต่ยิง `/api/health`
ซึ่งเป็นเส้นเดียวที่คุยกับฐานข้อมูลจริง หน้าแรกขึ้น 200 ได้ทั้งที่ต่อฐานข้อมูลไม่ได้เลย
ถ้าเห็น "เว็บต่อฐานข้อมูลได้" แปลว่าใช้งานได้จริง ไม่ใช่แค่เว็บเซิร์ฟเวอร์ยังหายใจ

ไม่ทำให้ 3 อย่าง เพราะต้องมีคนตัดสินใจ: พิธีสร้างกุญแจบัตร ([§3.3](#33-พิธีสร้างกุญแจบัตร-ปีละครั้ง-10-นาที)) ·
นำเข้ารายชื่อนักศึกษา (ต้องมีไฟล์จากสโมสรฯ) · ลบข้อมูล ([§5](#5-ขึ้นปีใหม่))

## 3. ติดตั้งครั้งแรก (ทำครั้งเดียว)

> 📌 **ถ้าคณะเคยติดตั้งรุ่นปีที่แล้วอยู่แล้ว** ไม่ต้องอ่านทั้งหัวข้อนี้ — ข้ามไป
> [§3.0 อัปเกรดจากรุ่นปีที่แล้ว](#30-อัปเกรดจากรุ่นปีที่แล้ว-ทำครั้งเดียว) ซึ่งบอกเฉพาะส่วนที่ต่างออกไป

### 3.0 อัปเกรดจากรุ่นปีที่แล้ว (ทำครั้งเดียว)

รุ่นนี้ยังเป็นระบบตัวเดิม เซิร์ฟเวอร์เดิม Docker เหมือนเดิม แต่มี 4 อย่างที่ต้องทำเพิ่ม
เพราะโครงสร้างความปลอดภัยเปลี่ยนไป ทำตามลำดับนี้:

**1. เพิ่มบัญชีฐานข้อมูลตัวที่สอง** — ปีที่แล้วเว็บต่อฐานข้อมูลด้วยบัญชีสิทธิ์เต็มบัญชีเดียว
ปีนี้แยกเป็นสองบัญชี เพื่อให้ตัวเว็บ **เพิ่มบัตรได้แต่ลบบัตรไม่ได้** (ดูเหตุผล [§3.5](#35-ทำไมต้องมีบัญชีฐานข้อมูล-2-ตัว))

```sql
CREATE ROLE fms_app LOGIN PASSWORD '<<สุ่มใหม่ เก็บใน .env เท่านั้น>>';
GRANT CONNECT ON DATABASE fms_election TO fms_app;
GRANT USAGE  ON SCHEMA public TO fms_app;
```

บัญชีเดิมที่ใช้อยู่กลายเป็น `fms_migrate` (ไม่ต้องสร้างใหม่ ใช้ตัวเดิมได้)

**2. พิธีสร้างกุญแจบัตรลงคะแนน** — ของใหม่ปีนี้ ปีที่แล้วบัตรยังไม่ได้เข้ารหัส
ทำตาม [§3.3](#33-พิธีสร้างกุญแจบัตร-ปีละครั้ง-10-นาที) แล้วเพิ่มสองบรรทัดนี้ใน `.env`:
`ELECTION_BALLOT_PUBLIC_KEY` และ `BALLOT_CHAIN_SECRET`
**ถ้าไม่มีสองตัวนี้ ระบบจะไม่รับโหวตเลย** (ตั้งใจให้ปิดตัวเองดีกว่าเก็บบัตรแบบไม่เข้ารหัส)

**3. แก้ `.env` ตามนี้**

| ทำอะไร | ตัวแปร |
|---|---|
| **ลบทิ้ง** (โค้ดไม่อ่านแล้ว) | `ADMIN_PASSWORD_AUTH_EXTRA` · `ADMIN_STUDENT_IDS` · `ADMIN_PRIVATE_KEY` · `ADMIN_AUTH_SECRET` · `NEXT_PUBLIC_ADMIN_PUBLIC_KEY` · `NEXT_PUBLIC_ADMIN_AUTH_SECRET` |
| **เพิ่มใหม่** | `MIGRATE_DATABASE_URL` · `ELECTION_BALLOT_PUBLIC_KEY` · `BALLOT_CHAIN_SECRET` |
| **สุ่มค่าใหม่** | `ADMIN_JWT_SECRET` · `NEXTAUTH_SECRET` (ของเดิมอยู่มานาน ถือว่าควรเปลี่ยน) |
| **เปลี่ยนค่า** | `DATABASE_URL` → ชี้ไปบัญชี `fms_app` ตัวใหม่ |

**4. อัปเดตแล้วล็อกสิทธิ์**

```bash
sh scripts/backup.sh                                     # สำรองของปีที่แล้วก่อน
git pull
sh scripts/setup.sh                                      # migrate + build + เปิดใหม่
psql "<fms_migrate>" -f scripts/sql/ballot-grants.sql    # ล็อกสิทธิ์ตารางบัตร (ใหม่ปีนี้)
npm run preflight                                        # ⭐ ต้องขึ้น "app can create parties/members"
node scripts/admin.js --grant <รหัส นศ. ของกรรมการ>       # ทีละคน
node scripts/admin.js --rotate-password                  # รหัสกลาง ส่งให้สโมสรฯ
```

> ⚠️ **ปีที่แล้วติดตรงนี้** — เพิ่มข้อมูลพรรคจากหน้าแอดมินไม่ได้ แต่ลบได้ อาการนี้ไม่ใช่สิทธิ์
> ตาราง แต่เป็นสิทธิ์ **sequence**: การ INSERT ต้องขอเลข id ตัวถัดไปจาก `Candidate_id_seq`
> ส่วน DELETE ไม่ต้องใช้ เลยยังทำงานได้ ทำให้ดูเหมือนสิทธิ์ครบแล้ว
> ไฟล์ `ballot-grants.sql` ปีนี้ให้สิทธิ์ sequence ครบแล้ว รวมถึงตารางที่จะสร้างในอนาคต
> และ `npm run preflight` จะทดลอง insert จริงแล้ว rollback ให้ดูว่าผ่านหรือไม่ **อย่าข้ามข้อนี้**

**สิ่งที่เปลี่ยนแล้วพี่ต้องรู้ แต่ไม่ต้องทำอะไร**

- **การเข้าหน้าแอดมินเปลี่ยนไปทั้งหมด** — เดิมใช้รหัสจาก env ตอนนี้เป็น "รหัส นศ. ที่ถูกตั้งสิทธิ์
  + รหัสกลางหนึ่งตัวที่เก็บเป็น hash ในฐานข้อมูล" ([§4](#4-งานที่สโมสรฯ-จะขอมา))
- **การล็อกอินด้วย PSU SSO ไม่ให้สิทธิ์แอดมินอีกแล้ว** — เดิมบัญชีที่อยู่กลุ่ม staff ของ ม.อ.
  เข้า API ฝั่งแอดมินได้โดยไม่ต้องใช้รหัส ตอนนี้ปิดแล้ว
- **หน้าแอดมินไม่มีปุ่มลบข้อมูลแล้ว** — การล้างข้อมูลขึ้นปีใหม่เป็นงานฝั่งเซิร์ฟเวอร์ ([§5](#5-ขึ้นปีใหม่))
- **ระบบธีม (template)** — สโมสรฯ **เลือก** หน้าตาเว็บเองได้ทุกปีจากหน้าแอดมิน (เลือกจากธีม
  สำเร็จที่มีให้ ไม่ใช่ตัวแก้แบบลากวาง) ไม่ต้องแก้โค้ด ไม่ต้อง deploy ใหม่ นี่คือเหตุผลหลักที่
  รุ่นนี้ตั้งใจให้ใช้ต่อได้หลายปีโดยไม่ต้องมีคนเขียนโค้ด · ตัวธีมอยู่ในโค้ด ไม่ได้อยู่ในฐานข้อมูล
  ([§8.2](#82-ธีมหน้าเว็บอยู่ในโค้ด-ไม่ได้อยู่ในฐานข้อมูล))

### 3.1 ของที่ต้องมีก่อน

- เครื่อง Linux ที่มี Docker และ Docker Compose
- PostgreSQL — สร้างเองหรือให้ docker สร้างก็ได้ รายละเอียดสิทธิ์ที่ต้องการอยู่ใน [§3.5](#35-ทำไมต้องมีบัญชีฐานข้อมูล-2-ตัว)
- ค่า PSU SSO ปีนั้น (client id / client secret / redirect uri) จาก IT ม.อ.
- ไฟล์รายชื่อนักศึกษาผู้มีสิทธิ์ จากสโมสรฯ

### 3.2 ตั้งค่า `.env`

สร้างไฟล์ `.env` ในโฟลเดอร์โปรเจกต์:

```
DATABASE_URL=              # ของบัญชี fms_app (บัญชีที่เว็บใช้)
MIGRATE_DATABASE_URL=      # ของบัญชี fms_migrate (ใช้ตอนสร้าง/แก้ตารางเท่านั้น)
NEXTAUTH_SECRET=           # สุ่มด้วย: openssl rand -base64 32
NEXTAUTH_URL=              # URL จริง เช่น https://xxx.psu.ac.th/fms-ovs
NEXT_PUBLIC_BASE_PATH=/fms-ovs
BASE_PATH=/fms-ovs
ADMIN_JWT_SECRET=          # สุ่มด้วย: openssl rand -hex 32
AUTHENTIK_CLIENT_ID=
AUTHENTIK_CLIENT_SECRET=
AUTHENTIK_REDIRECT_URI=
ELECTION_BALLOT_PUBLIC_KEY=   # ได้จาก §3.3
BALLOT_CHAIN_SECRET=          # ได้จาก §3.3
POSTGRES_PASSWORD=            # เฉพาะกรณีให้ docker สร้างฐานข้อมูลให้เอง
```

**รหัสผ่านแอดมินไม่อยู่ในไฟล์นี้** อยู่ในฐานข้อมูลเป็น bcrypt hash ตั้งด้วยคำสั่งใน [§4](#4-งานที่สโมสรฯ-จะขอมา)

#### ⚠️ สอง URL นี้ไม่ใช่ตัวเดียวกัน — พลาดตรงนี้แล้วเว็บจะขึ้นแต่ใช้งานไม่ได้

| ตัวแปร | ใครใช้ | มองฐานข้อมูลจากไหน |
|---|---|---|
| `DATABASE_URL` | ตัวเว็บ (อยู่ในคอนเทนเนอร์) | **จากในคอนเทนเนอร์** |
| `MIGRATE_DATABASE_URL` | คำสั่งที่คุณพิมพ์ (migrate, `admin.js`, `preflight`) | **จากเครื่องนี้** |

ในคอนเทนเนอร์ คำว่า `localhost` หมายถึงตัวคอนเทนเนอร์เอง ไม่ใช่เครื่องเซิร์ฟเวอร์
ถ้า `DATABASE_URL` เขียนว่า `localhost` แล้วเอาไปรันใน docker ผลคือ **หน้าแรกยังขึ้น 200 ตามปกติ
แต่ล็อกอินไม่ได้ ข้อมูลไม่ขึ้น `/api/health` = 503** ซึ่งดูเผิน ๆ เหมือนติดตั้งสำเร็จ

ตั้งค่าตามกรณีที่ใช้:

| ฐานข้อมูลอยู่ที่ไหน | `DATABASE_URL` | `MIGRATE_DATABASE_URL` |
|---|---|---|
| เซิร์ฟเวอร์ฐานข้อมูลของคณะ (กรณีปกติ) | `postgresql://fms_app@dbhost:5432/…` | `postgresql://fms_migrate@dbhost:5432/…` |
| ฐานข้อมูลที่ docker สร้างให้ (compose มี service `db`) | `postgresql://postgres@db:5432/…` | `postgresql://postgres@localhost:5433/…` (ต้องเปิด port ดูคอมเมนต์ใน `docker-compose.yml`) |
| ฐานข้อมูลติดตั้งบนเครื่องเดียวกันแต่ไม่ได้อยู่ใน docker | `postgresql://…@host.docker.internal:5432/…` | `postgresql://…@localhost:5432/…` |

`setup.sh` ตรวจข้อนี้ให้ตั้งแต่ต้น และจะหยุดพร้อมบอกวิธีแก้ถ้าตั้งผิด

### 3.3 พิธีสร้างกุญแจบัตร (ปีละครั้ง ~10 นาที)

ทำร่วมกับ **พี่สตาฟคณะ** และตัวแทนสโมสรฯ บนเครื่องที่ไว้ใจได้:

```bash
node scripts/generate-election-keys.js --out key-2569.enc
```

- **public key + chain secret** → วางใน `.env` บนเซิร์ฟเวอร์ (chain secret เก็บสำเนานอกเครื่องด้วย)
- **ไฟล์ `key-2569.enc`** → มี private key อยู่ข้างใน เข้ารหัสด้วยรหัสผ่านที่คุณตั้งตอนรัน
  ก๊อปไปเก็บ **2 ที่ที่คณะคุมเอง** แล้วลบไฟล์ต้นทางทิ้ง
  **ห้ามอยู่บนเซิร์ฟเวอร์และห้ามอยู่ในชุดสำรองเดียวกับฐานข้อมูลเด็ดขาด**
  ใช้เฉพาะกรณีมีข้อพิพาทแล้วต้องนับคะแนนใหม่ต่อหน้ากรรมการ
  ถ้าหาย ผลเลือกตั้งไม่เสีย เสียแค่ความสามารถนับใหม่

> **แยกไฟล์กับรหัสผ่านให้คนละคนถือ** — ให้ไฟล์คนหนึ่ง บอกรหัสผ่านอีกคนหนึ่ง คนเดียวเปิดไม่ได้
> · กรอกใบบันทึกผู้ถือกุญแจใน `docs/BALLOT-SECURITY-GUIDE.md` §7 ไว้ด้วย ไม่งั้นอีกสองปีจะไม่มีใครจำได้ว่าอยู่กับใคร

> ⚠️ **ห้ามใช้กุญแจของเครื่องทดสอบบนเครื่องจริง** และเปลี่ยนกุญแจได้ก่อนบัตรใบแรกลงกล่อง
> เท่านั้น — เปลี่ยนทีหลังบัตรเก่าจะเปิดด้วยกุญแจใหม่ไม่ได้
>
> ถ้ากุญแจสองตัวใน `.env` ไม่ครบ ระบบจะปิดรับโหวตทันที แทนที่จะเก็บบัตรแบบไม่เข้ารหัส

**อ่านก่อนทำครั้งแรก:** `docs/BALLOT-SECURITY-GUIDE.md` — อธิบายว่ากุญแจแต่ละดอกทำอะไร
หายหรือหลุดแล้วเสียอะไร เก็บไว้นานแค่ไหน และต้องทำยังไงเมื่อเกิดเหตุ

### 3.4 ติดตั้งและเปิดระบบ

```bash
sh scripts/setup.sh --admin <รหัส นศ. ของประธานสโมสรฯ>
node scripts/admin.js --rotate-password    # ได้รหัสกลาง ส่งให้สโมสรฯ
npm run import-students -- <ไฟล์รายชื่อ>
```

จากนั้นบอกสโมสรฯ ให้เข้าไปตั้งค่าการเลือกตั้งและกดปุ่ม "ตรวจความพร้อมระบบ" เอง

### 3.5 ทำไมต้องมีบัญชีฐานข้อมูล 2 ตัว

ไม่ใช่ database 2 อัน — ข้อมูลชุดเดียวกัน แต่เข้าถึงด้วยสิทธิ์คนละระดับ

| บัญชี | ใช้ตอนไหน | สิทธิ์ |
|---|---|---|
| `fms_migrate` | เฉพาะตอนสร้าง/แก้โครงสร้างตาราง | เต็ม |
| `fms_app` | ตัวเว็บใช้ตลอดเวลาที่รันอยู่ | จำกัด — **เพิ่มบัตรได้ แก้/ลบบัตรไม่ได้** |

สร้างครั้งเดียวตอนติดตั้ง (คำสั่งอยู่ในหัวไฟล์ `scripts/sql/ballot-grants.sql`) แล้ว `setup.sh`
จะรันไฟล์นั้นให้เอง เพื่อบังคับสิทธิ์ตามตาราง

นี่คือกลไกที่ทำให้พูดได้ว่า **ผลเลือกตั้งที่ลงไปแล้วแก้ไม่ได้ แม้แต่คนดูแลระบบเอง** — ถ้าเว็บ
ต่อฐานข้อมูลด้วยบัญชีสิทธิ์เต็ม ข้อจำกัดนี้ไม่มีความหมายเลย

|---|---|---|
| เพิ่มกรรมการเป็นแอดมิน | `node scripts/admin.js --grant <รหัส นศ.>` | ถ้าขึ้น "ไม่พบ" ให้เขาล็อกอินหน้าเว็บด้วย PSU Passport หนึ่งครั้งก่อน แล้วรันซ้ำ · ไม่ต้องออกรหัสใหม่ รหัสกลางเดิมใช้ได้เลย |

| ลืมรหัสกลาง / รหัสหลุด | `node scripts/admin.js --rotate-password` | รหัสขึ้นจอครั้งเดียว · **รหัสเดิมตายทันที** ทุกคนต้องได้รหัสใหม่ → แจ้งเขาก่อนกด |

| ล้างข้อมูลปีเก่า / คะแนนซ้อม | [§5](#5-ขึ้นปีใหม่) | สำรองก่อนเสมอ |
| ตรวจคะแนนก่อนประกาศผล | `node scripts/reconcile-scores.js` | ตอบเขาว่าตรงกันทั้งสามทางหรือไม่ ก่อนเขากดเผยแพร่ผล |
| มีคนตั้งคำถามกับผล | `node scripts/verify-ballot-chain.js` | ถ้าถึงขั้นนับใหม่ ต้องใช้ไฟล์กุญแจ ทำ offline ต่อหน้ากรรมการ (`docs/BALLOT-SECURITY-GUIDE.md` §8) |
| ปุ่มตรวจความพร้อมขึ้นแดง | `npm run preflight` | เห็นสาเหตุฝั่งเซิร์ฟเวอร์ชัดกว่าหน้าเว็บ |

> **ถ้าฐานข้อมูลอยู่ใน docker** คำสั่ง `node scripts/admin.js …` ที่พิมพ์บนเครื่องต้องชี้ไป
> ฐานข้อมูลตัวเดียวกับที่เว็บใช้ ไม่งั้นจะไปแก้ผิดฐาน (แล้วงงว่าทำไมสิทธิ์ไม่มีผล) — ใส่นำหน้า:
>
> ```bash
> DATABASE_URL="$MIGRATE_DATABASE_URL" node scripts/admin.js --list
> ```
>
> กรณีใช้ฐานข้อมูลของคณะ (ปกติ) ไม่ต้องใส่อะไรนำหน้า

**เรื่องรหัสกลาง** — เป็นรหัสตัวเดียวที่กรรมการทั้งชุดใช้ร่วมกัน แต่ระบบยังรู้ว่าใครกดอะไร
เพราะตัวตนมาจากรหัส นศ. ที่ล็อกอิน · รหัสกลางอย่างเดียวเปิดอะไรไม่ได้ ต้องเป็นคนที่ถูก
`--grant` ไว้ด้วย · ในฐานข้อมูลเก็บแค่ bcrypt hash เปิดดูย้อนหลังไม่ได้

**ส่งรหัสให้เขายังไง** — ส่งตัวต่อตัวหรือช่องทางที่ปิด แล้วให้เก็บลงตัวจัดการรหัสผ่าน
ห้ามพิมพ์ลงเอกสาร ไฟล์ในโปรเจกต์ หรือแชทกลุ่มที่ค้างนาน ๆ

## 8. ฐานข้อมูล

โครงสร้างทั้งหมดสร้างจาก `prisma/migrations/` ด้วย `npx prisma migrate deploy`
**ไม่ต้องสร้างตารางเองด้วยมือ และไม่ต้องแก้ตารางเองด้วยมือ** ถ้าโครงสร้างเปลี่ยน จะมาพร้อม
ไฟล์ migration ใหม่ในโค้ด และ `setup.sh` จะรันให้ตอนอัปเดต

### 8.1 มีตารางอะไรบ้าง

| ตาราง | เก็บอะไร | หมายเหตุสำคัญ |
|---|---|---|
| `User` | นักศึกษาผู้มีสิทธิ์ + แอดมิน · รหัส นศ. ชื่อ อีเมล คณะ สาขา ชั้นปี | `isVoted` = ใช้สิทธิ์แล้วหรือยัง · `isAdmin` = สิทธิ์แอดมิน · `passwordHash` มีเฉพาะบัญชีสำรอง · **ไม่มีคอลัมน์ไหนบอกว่าเลือกพรรคใด** |
| `Candidate` | พรรค · ชื่อ เบอร์ โลโก้ สี นโยบาย · ช่องทางติดต่อ | `score` = คะแนนจริง (บวกตอนโหวต) · เบอร์ `0` = งดออกเสียง, `-1` = ไม่รับรอง · `socials` = IG/FB/TikTok ที่แอดมินกรอก (เก็บเป็น URL เต็มที่ผ่านการตรวจแล้ว) |
| `Member` | สมาชิกพรรค · ชื่อ ตำแหน่ง รูป | ผูกกับ `Candidate` |
| `Ballot` | **หีบบัตร** · บัตรที่เข้ารหัสแล้ว 1 แถว = 1 ใบ | ไม่มี `userId` ไม่มีเวลาละเอียด · `payload` เข้ารหัส RSA · `prevHash`/`rowHash` ร้อยเป็นโซ่กันแก้ · **บัญชี `fms_app` เพิ่มได้อย่างเดียว ลบ/แก้ไม่ได้** |
| `ChainHead` | ปลายโซ่ของหีบบัตร (แถวเดียว) | ล็อกแถวนี้ตอนโหวต = กันโหวตพร้อมกันแล้วโซ่ขาด |
| `AdminAuditLog` | บันทึกทุกคำสั่งของแอดมิน · ใคร ทำอะไร เมื่อไหร่ | เขียนเพิ่มได้อย่างเดียว |
| `SystemConfig` | ตั้งค่าระบบ (แถวเดียว id=1) · โหมด วันเวลา ธีมที่เลือกไว้ | `adminPasswordHash` = รหัสกลางของแอดมิน (bcrypt) · `activeTemplateId` = ธีมที่ใช้อยู่ · `pageLayout`/`themeConfig` = ของเหลือจากระบบเดิม ดู [§8.2](#82-ธีมหน้าเว็บอยู่ในโค้ด-ไม่ได้อยู่ในฐานข้อมูล) |
| `Template` | ตารางของระบบรุ่นก่อน — **ปกติว่างเปล่า** | ธีมที่เลือกได้ทั้งหมดอยู่ใน**โค้ด** ไม่ใช่ตารางนี้ · ไม่เกี่ยวกับคะแนน · อ่าน [§8.2](#82-ธีมหน้าเว็บอยู่ในโค้ด-ไม่ได้อยู่ในฐานข้อมูล) ก่อนแตะ |

**ข้อที่ต้องรู้ข้อเดียวถ้าจำอย่างอื่นไม่ได้:** ไม่มีที่ไหนในฐานข้อมูลที่บอกได้ว่า
**ใครเลือกพรรคไหน** — `User.isVoted` บอกแค่ว่ามาใช้สิทธิ์แล้ว ส่วน `Ballot` เก็บตัวเลือก
ในรูปที่เข้ารหัสและไม่มีเส้นเชื่อมกลับไปหาคน แม้แต่ใน backup ก็ไม่มี

### 8.2 ธีมหน้าเว็บอยู่ในโค้ด ไม่ได้อยู่ในฐานข้อมูล

หัวข้อนี้แยกไว้เพราะฐานข้อมูลยังมีร่องรอยของระบบรุ่นก่อนค้างอยู่ ถ้าไม่รู้ที่มา จะอ่านชื่อ
ตารางแล้วเข้าใจผิดว่ามีระบบแก้หน้าเว็บซ่อนอยู่ที่ไหน แล้วไปหาไม่เจอ

**เมื่อก่อน** หน้าแอดมินมีตัวแก้หน้าเว็บอยู่จริง — ลากสลับลำดับ section, แก้สีทีละชิ้น,
สร้าง/คัดลอก/ลบธีมของตัวเองได้ ธีมที่สร้างจากหน้านั้นถูกเก็บเป็นแถวในตาราง `Template`
และค่าที่แก้ทีละชิ้นถูกเก็บใน `SystemConfig.pageLayout`

**ตอนนี้ตัวแก้หน้าเว็บถูกเลิกใช้แล้ว** ที่เหลือคือ **"เลือกธีมสำเร็จ"** อย่างเดียว — สโมสรฯ
เปิดแท็บธีม เลือก 1 จาก 6 ตระกูล (แต่ละตระกูลมีชุดสีให้เลือกอีก รวม 23 แบบ) แล้วกด Apply
จบ **ไม่มีสร้าง ไม่มีแก้ ไม่มีลบ** ในหน้าแอดมิน

ตัวธีมทุกแบบเป็น **ไฟล์โค้ด** ใน `src/components/admin/editor/templates/builtIn/`
ไม่ใช่ข้อมูลในฐานข้อมูล ผลที่ตามมาซึ่งเกี่ยวกับงานคุณโดยตรง:

| เรื่อง | ความจริงของระบบตอนนี้ |
|---|---|
| ตาราง `Template` | **ว่างเปล่า** ในการติดตั้งปกติ (`prisma/seed.js` ไม่ได้ใส่อะไรลงไป) ธีมที่เห็นในหน้าแอดมินไม่ได้มาจากตารางนี้เลย |
| เพิ่มธีมใหม่ในปีถัดไป | ทีมพัฒนาเขียนไฟล์ธีมใหม่แล้ว deploy — **ไม่ใช่** การ `INSERT` แถวลงฐานข้อมูล คนที่มาทำต่อก็ทำวิธีเดียวกันนี้ |
| `SystemConfig.activeTemplateId` | ที่เดียวที่บอกว่าตอนนี้ใช้ธีมไหน (เก็บเป็น slug เช่น `receipt`, `original`) — ค่าที่ต้องมีติดไปกับ backup |
| `SystemConfig.pageLayout` | ยังมีการอ่านอยู่ (โครงลำดับ section หน้าแรก + ตัวเลือกหน้าลงคะแนน) แต่ **ไม่มีหน้าจอให้ใครแก้** ระบบเขียนทับให้เองตอนกด Apply เพื่อล้างค่าที่ตัวแก้รุ่นเก่าทิ้งค้างไว้ |
| `SystemConfig.themeConfig` | ไม่มีโค้ดไหนอ่านค่านี้แล้ว — คอลัมน์ตายที่ยังไม่ได้ถอด |
| `Template.authorId` → `User` | foreign key ของระบบเดิม (ใครสร้างธีมนั้น) ไม่มีอะไรเขียนลงไปแล้ว |

**ทำไมยังไม่ลบทิ้งให้หมด** — คอลัมน์และตารางเหล่านี้ถูกอ้างในโค้ดหลายจุด และฐานข้อมูลของ
ปีก่อนยังมีค่าเก่าค้างอยู่ การถอดออกต้องมาพร้อม migration ที่ทดสอบแล้ว งานนั้นจะทำในรอบ
ล้างระบบประจำปี ไม่ทำระหว่างช่วงเลือกตั้ง

> ⚠️ **อย่า `DROP TABLE "Template"` หรือ `DROP COLUMN` เองด้วยมือ** แม้จะเห็นว่าไม่มีใครใช้
> ถ้าลบตาราง `Template` โค้ดที่รวมรายชื่อธีมจะยิง error ลง log ทุกครั้ง (มี try/catch คลุมไว้
> จึงไม่ล้ม แต่รบกวน) และถ้าลบ **คอลัมน์** ใน `SystemConfig` เว็บจะพังทั้งระบบทันที เพราะ
> Prisma อ่านทุกคอลัมน์ตามที่ประกาศไว้ใน schema · ทั้งสองกรณีทำให้โครงสร้างจริงไม่ตรงกับ
> migration ที่บันทึกไว้ รอบอัปเดตปีถัดไปจะเจอปัญหาที่หาสาเหตุยาก

### 8.3 สร้างฐานข้อมูลจากศูนย์

**ทางปกติ — ไม่ต้องแตะ SQL เลย** `sh scripts/setup.sh` ทำให้แล้ว (มันเรียก
`prisma migrate deploy` ซึ่งรู้ว่าฐานข้อมูลอยู่รุ่นไหน และอัปเดตต่อได้ในปีถัดไป)

**ถ้าอยากสร้างด้วย SQL ตรง ๆ** เช่น DBA ขอดูก่อนว่าจะสร้างอะไรบ้าง หรือเครื่องนั้นรัน node ไม่ได้:

```bash
psql "<fms_migrate>" -f scripts/sql/schema.sql          # สร้างทุกตาราง + แถวเริ่มต้นของโซ่บัตร
psql "<fms_migrate>" -f scripts/sql/ballot-grants.sql   # ล็อกสิทธิ์ตารางบัตร
```

`scripts/sql/schema.sql` คือคำสั่ง `CREATE TABLE` ทั้งหมดในไฟล์เดียว generate จาก schema จริง
เปิดอ่านก่อนรันได้ (ทดสอบแล้วว่าสร้างฐานข้อมูลได้ครบเท่ากับทาง migrate ทุกคอลัมน์)

> ⚠️ ถ้าใช้ทาง SQL ต้องบอก prisma ว่า migration ทั้งหมดถือว่าลงแล้ว ไม่งั้นการอัปเดตครั้งถัดไป
> จะพยายามสร้างตารางซ้ำ — คำสั่งอยู่ในหัวไฟล์ `schema.sql`

### 8.4 schema ตามที่เขียนไว้ในไฟล์

นี่คือ `prisma/schema.prisma` ในโค้ด ซึ่งเป็นต้นทางของทุกตาราง — แก้ที่นี่ที่เดียวแล้วสร้าง
migration ตาม ห้ามไปแก้ตารางในฐานข้อมูลด้วยมือ เพราะรอบอัปเดตถัดไปจะไม่ตรงกัน
(ทุกคอลัมน์ตรงกับไฟล์จริง คำอธิบายภาษาไทยเติมมาให้อ่านง่ายเท่านั้น)

```prisma
model User {
  id               Int     @id @default(autoincrement())
  studentId        String  @unique
  name             String?
  email            String?
  facultyId        String?
  departmentId     String?
  role             String  @default("student")
  passwordHash     String?
  gender           String?
  major            String?
  titleName        String?
  subKeyId         String?
  subMajorId       String?
  subMajorNameThai String?
  year             String?
  yearStatus       String?

  isVoted         Boolean   @default(false)
  votedAt         DateTime? // เวลาที่คนนี้มาใช้สิทธิ์ — ข้อมูลของตัวเอง ไม่ใช่ความลับ
  //                           ไม่มีเส้นเชื่อมไปยังบัตรใบไหน: ตัวเลือกอยู่ในบัตรที่
  //                           เข้ารหัสและสาวกลับไม่ได้ (v2-SEC)
  isFormCompleted Boolean   @default(false)
  createdAt       DateTime  @default(now())
  isAdmin         Boolean   @default(false)

  // ของระบบแก้หน้าเว็บรุ่นก่อน (ใครสร้างธีมไหน) — ไม่มีอะไรเขียนลงไปแล้ว ดู §8.2
  authoredTemplates Template[] @relation("AuthoredTemplates")
}

model Member {
  id        Int    @id @default(autoincrement())
  studentId String @unique
  name      String
  number    Int    @default(0)

  imageUrl      String
  modalImageUrl String?

  major    String?
  position String?

  candidateId Int
  candidate   Candidate @relation(fields: [candidateId], references: [id])
}

model Candidate {
  id      Int     @id @default(autoincrement())
  name    String  @unique
  number  Int     @unique
  slogan  String?
  logoUrl String?
  color   String? // สีประจำพรรค (hex) แอดมินตั้งเอง

  groupImageUrls   Json?
  officialImageUrl String?
  mobileHeroImage  Json?

  logoMeaning String?
  missions    Json?
  policies    Json?

  members Member[]

  score Int @default(0)   // คะแนนจริง บวกทีละหนึ่งตอนลงคะแนน

  // ช่องทางติดต่อของพรรค — เก็บเป็น Json ก้อนเดียว เพิ่มช่องทางใหม่ได้โดยไม่ต้อง migrate
  socials Json?
}

// ============================================================
// v2-SEC — หีบบัตรนิรนาม เข้ารหัส และตรวจการแก้ไขได้
// ============================================================
//
// บัตรหนึ่งใบไม่มี userId และไม่มีเวลาละเอียด — เชื่อมกลับไปหาผู้ลงคะแนนไม่ได้
// เชิงโครงสร้าง `payload` คือ ciphertext RSA-OAEP ของ {c: candidateId, n: nonce}
// เข้ารหัสด้วย public key ของการเลือกตั้ง ส่วน private key ไม่เคยอยู่บนเซิร์ฟเวอร์
// (ใช้เฉพาะตอนมีข้อพิพาท แบบ offline) คะแนนที่ระบบแสดงคือ Candidate.score
// ดังนั้นกุญแจส่วนตัวหาย = เสียแค่ความสามารถนับใหม่ ไม่เสียผลเลือกตั้ง
//
// ทุกแถวถูกร้อยด้วย HMAC (prevHash → rowHash) การแก้บัตรเก่าเงียบ ๆ จะทำให้โซ่ขาด
// และตรวจเจอได้ด้วย scripts/verify-ballot-chain.js · บัญชีฐานข้อมูลของแอปมีสิทธิ์
// INSERT อย่างเดียวบนตารางนี้ (scripts/sql/ballot-grants.sql) ตัวแอปจึงแก้บัตรไม่ได้
model Ballot {
  seq        Int    @id @default(autoincrement()) // ลำดับในโซ่
  payload    String  // base64 RSA-OAEP(sha256) ของ JSON {c: candidateId, n: nonce}
  hourBucket String? // หยาบระดับชั่วโมง เช่น "2569-02-06T09" — ไม่เคยเก็บเวลาละเอียด
  prevHash   String  // rowHash ของแถว seq-1 (แถวแรก = "GENESIS")
  rowHash    String  // HMAC-SHA256(BALLOT_CHAIN_SECRET, prevHash|payload|seq)
}

// ปลายโซ่ มีแถวเดียวเสมอ (id=1) — คำสั่ง UPDATE ... WHERE id=1 ในทรานแซกชันของการ
// ลงคะแนนจะล็อกแถวนี้ ทำให้บัตรที่ลงพร้อมกันสองใบยังได้โซ่ที่ต่อเนื่องไม่ขาดตอน
model ChainHead {
  id   Int    @id @default(1)
  head String @default("GENESIS")
  seq  Int    @default(0)
}

// บันทึกคำสั่งของแอดมินแบบเขียนเพิ่มอย่างเดียว (เปลี่ยนโหมด รับรองผล ฯลฯ)
model AdminAuditLog {
  id        Int      @id @default(autoincrement())
  action    String
  detail    String?
  actor     String?  // รหัส นศ. ของแอดมินที่สั่ง มาจาก cookie ที่ตรวจแล้ว
  createdAt DateTime @default(now())

  @@index([createdAt])
}

model SystemConfig {
  id            Int      @id @default(1)
  isVoteOpen    Boolean  @default(false) // ของเก่า ไม่ได้ใช้ตัดสินใจแล้ว
  showResult    Boolean  @default(false)
  systemMode    String   @default("AUTO")
  googleFormUrl String?
  pageLayout    Json?    // โครงหน้าแรก + ตัวเลือกหน้าลงคะแนน — ไม่มีหน้าจอให้แก้แล้ว
  //                        ระบบเขียนทับเองตอนกด Apply ธีม (§8.2)
  themeConfig   Json?    // คอลัมน์ตาย ไม่มีโค้ดไหนอ่าน (§8.2)
  globalConfig  Json?    // วันเวลาเลือกตั้ง + ธงรับรองผล
  updatedAt     DateTime @updatedAt

  // ธีมที่ใช้อยู่ เก็บเป็น slug ของธีมในโค้ด เช่น "receipt" "original"
  // ค่าตั้งต้น "classic" เป็นชื่อเก่าที่ระบบชี้ไปที่ธีม original ให้อยู่แล้ว
  activeTemplateId String? @default("classic")

  // รหัสกลางของแอดมิน เก็บเป็น bcrypt hash ตัวเดียวทั้งชุดกรรมการ
  // ตัวตนมาจากรหัส นศ. ที่พิมพ์ตอนล็อกอิน + User.isAdmin
  // เขียนด้วย scripts/admin.js --rotate-password · ไม่มีที่ไหนเก็บรหัสตัวจริง
  adminPasswordHash String?
}

// ตารางของระบบแก้หน้าเว็บรุ่นก่อน — เก็บธีมที่แอดมินสร้างเองจากตัวแก้ในหน้าเว็บ
// ระบบนั้นถูกเลิกใช้แล้ว ธีมทั้งหมดตอนนี้เป็นไฟล์โค้ด ตารางนี้จึงว่างในการติดตั้งปกติ
// เหลือไว้เพราะโค้ดยังอ้างถึงตอนรวมรายชื่อธีม และฐานข้อมูลปีก่อนอาจมีแถวค้าง (§8.2)
model Template {
  id String @id @default(cuid())

  slug        String  @unique
  name        String
  description String?

  authorId Int?
  author   User? @relation("AuthoredTemplates", fields: [authorId], references: [id])

  isBuiltIn  Boolean @default(false)
  isLocked   Boolean @default(false)
  forkedFrom String?
  visibility String  @default("private")

  pages    Json
  elements Json
  theme    Json

  schemaVersion String  @default("v1")
  archivedYear  String?

  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@index([authorId])
  @@index([isBuiltIn])
  @@index([isLocked])
  @@index([forkedFrom])
}
```

**ความสัมพันธ์ระหว่างตาราง**

```
Candidate 1 ──< Member          (Member.candidateId → Candidate.id)
User      1 ──< Template        (Template.authorId  → User.id)   ← ของระบบเดิม ไม่มีข้อมูลแล้ว

Ballot / ChainHead              ไม่เชื่อมกับตารางไหนเลย  ← ตั้งใจ
User / Candidate                ไม่มีเส้นเชื่อมถึงกัน     ← ตั้งใจ
```

สองบรรทัดล่างคือหัวใจของระบบ: **คะแนนอยู่ที่ `Candidate.score` · การมาใช้สิทธิ์อยู่ที่
`User.isVoted` · ตัวเลือกอยู่ในบัตรที่เข้ารหัส และไม่มี foreign key ใดเชื่อมสามอย่างนี้เข้าหากัน**
ตรวจเองได้บนเซิร์ฟเวอร์ของคุณ:

```bash
psql "<fms_migrate>" -c "\d+ \"Ballot\""    # ไม่มีคอลัมน์ไหนชี้ไปหา User
psql "<fms_migrate>" -c "\dt"               # รายชื่อตารางทั้งหมด
```

### 8.6 สิทธิ์ที่ต้องให้ — แยกตามงานจริงในหน้าแอดมิน

หัวข้อนี้มีไว้ให้ตั้งสิทธิ์ได้ถูกตั้งแต่รอบแรก ระบบมหาวิทยาลัยมักให้สิทธิ์แบบรัดกุม
ซึ่งเป็นเรื่องดี แต่ถ้าขาดไปข้อเดียวอาการที่โผล่มามักไม่ได้ชี้ไปที่สาเหตุเลย
(ปีที่แล้วเสียเวลากับเรื่องนี้ทั้งวัน — ดู [§3.0](#30-อัปเกรดจากรุ่นปีที่แล้ว-ทำครั้งเดียว))

ทั้งหมดนี้ `scripts/sql/ballot-grants.sql` ให้ครบอยู่แล้ว ตารางข้างล่างคือ "ทำไมต้องมี"
เผื่อต้องอธิบายกับฝ่ายความปลอดภัย หรือต้องตั้งเองทีละบรรทัด

#### งานในหน้าแอดมิน → เขียนอะไรลงตารางไหน

| งานที่กดในหน้าแอดมิน | ระบบทำอะไรกับฐานข้อมูลจริง | สิทธิ์ที่ขาดไม่ได้ |
|---|---|---|
| **เพิ่มพรรค** | `INSERT Candidate` → `INSERT Member` (ถ้ากรอกสมาชิกมาด้วย) → `UPDATE Candidate` (เติม path รูปหลังอัปโหลดเสร็จ) | `INSERT`,`UPDATE` บน `Candidate` · `INSERT` บน `Member` · **`USAGE`,`SELECT` บน `Candidate_id_seq` และ `Member_id_seq`** |
| **แก้ไขพรรค** | `UPDATE Candidate` · แล้ว `DELETE Member` ทั้งพรรค + `INSERT Member` ใหม่ทั้งชุด | `UPDATE` บน `Candidate` · `DELETE`,`INSERT` บน `Member` + sequence |
| **ลบพรรค** | `DELETE Member` ของพรรคนั้น → `DELETE Candidate` | `DELETE` บน `Member` **และ** `Candidate` |
| **เพิ่ม / แก้ / ลบสมาชิกพรรค** | เส้นทางเดียวกับ "แก้ไขพรรค" — ระบบเขียนรายชื่อสมาชิกใหม่ทั้งชุดทุกครั้ง ไม่ได้แก้ทีละแถว | `DELETE`,`INSERT` บน `Member` + sequence |
| **เปิดแท็บธีม (ดูรายชื่อธีม)** | `SELECT SystemConfig` + `SELECT Template` (ตัวธีมมาจากโค้ด ตารางแค่ถูกอ่านเผื่อมีแถวเก่าค้าง) | `SELECT` บน `SystemConfig` และ `Template` |
| **เปลี่ยนธีม (กด Apply) แล้วต้องบันทึกได้** | `UPDATE SystemConfig` — เขียน `activeTemplateId` และเขียน `pageLayout` ทับเพื่อล้างค่าที่ตัวแก้รุ่นเก่าทิ้งไว้ | `UPDATE` บน `SystemConfig` |
| **เปลี่ยนโหมดระบบ · เปิดเผยผล · รับรองผล** | `UPDATE SystemConfig` (ครั้งแรกสุดถ้ายังไม่มีแถวจะ `INSERT`) | `UPDATE`,`INSERT` บน `SystemConfig` |
| **ทุกคำสั่งของแอดมิน** | `INSERT AdminAuditLog` (บันทึกว่าใครสั่งอะไร) | `INSERT` บน `AdminAuditLog` + sequence |
| **นักศึกษาลงคะแนน** | `UPDATE User` (`isVoted`) · `UPDATE Candidate` (`score`) · `INSERT Ballot` · `UPDATE ChainHead` | ตามซ้าย — **`Ballot` ต้องเป็น INSERT อย่างเดียว** |
| **นำเข้ารายชื่อผู้มีสิทธิ์** (`import-students`) | `INSERT`/`UPDATE User` | `INSERT`,`UPDATE` บน `User` + sequence |
| **ให้/ถอดสิทธิ์แอดมิน** (`admin.js --grant/--revoke`) | `UPDATE User` (`isAdmin`) | `UPDATE` บน `User` |
| **ออกรหัสกลางใหม่** (`admin.js --rotate-password`) | `UPDATE SystemConfig` (`adminPasswordHash`) | `UPDATE` บน `SystemConfig` |
| **ล็อกอินแอดมิน** | `SELECT User` + `SELECT SystemConfig` | `SELECT` |

> **ไม่มีงาน "สร้าง / แก้ / ลบธีม" ในหน้าแอดมิน** ระบบเป็นการเลือกธีมสำเร็จอย่างเดียว
> ([§8.2](#82-ธีมหน้าเว็บอยู่ในโค้ด-ไม่ได้อยู่ในฐานข้อมูล)) ตาราง `Template` จึงถูกอ่านเท่านั้น
> ไม่มีเส้นทางไหนในหน้าเว็บที่เขียนลงตารางนั้น

> **สคริปต์ `admin.js` / `import-students` ใช้ `DATABASE_URL` ตัวเดียวกับเว็บ** (บัญชี `fms_app`)
> ไม่ได้ใช้บัญชี migrate — ถ้าตัดสิทธิ์ `UPDATE User` หรือ `UPDATE SystemConfig` ออก
> สองสคริปต์นี้จะพังทันที ทั้งที่หน้าเว็บยังดูปกติ

#### สรุปเป็นตารางสิทธิ์ต่อ table

อ่านสัญลักษณ์: **✓** = ต้องมี ไม่มีแล้วพัง · **✗** = ห้ามมี (ให้ไปจะเสียหลักการของระบบ) ·
**–** = ระบบไม่ได้ใช้ มีก็ไม่เป็นไร ไม่มีก็ไม่พัง

| ตาราง | SELECT | INSERT | UPDATE | DELETE | หมายเหตุ |
|---|:--:|:--:|:--:|:--:|---|
| `Candidate` | ✓ | ✓ | ✓ | ✓ | ลบพรรคต้องใช้ DELETE |
| `Member` | ✓ | ✓ | ✓ | ✓ | ทุกการแก้สมาชิก = ลบทั้งชุดแล้วเขียนใหม่ |
| `SystemConfig` | ✓ | ✓ | ✓ | ✗ | หัวใจของการบันทึกธีม/โหมด/รหัสกลาง |
| `Template` | ✓ | – | – | – | **ระบบใช้แค่ `SELECT`** · `ballot-grants.sql` ให้ครบทั้งสี่ตั้งแต่สมัยระบบเดิม — ปล่อยไว้ได้ ไม่กระทบหีบบัตร ถ้าฝ่ายความปลอดภัยขอให้รัดกุม ตัดสามตัวหลังออกได้โดยไม่กระทบงานของสตาฟ |
| `User` | ✓ | ✓ | ✓ | ✗ | ไม่ต้องให้ลบ — การลบผู้ใช้เป็นงาน DBA |
| `AdminAuditLog` | ✓ | ✓ | ✗ | ✗ | เขียนเพิ่มอย่างเดียว ห้ามแก้ประวัติ |
| `ChainHead` | ✓ | ✗ | ✓ | ✗ | แถวเดียว ล็อกตอนโหวต |
| **`Ballot`** | ✓ | ✓ | **✗** | **✗** | **จุดสำคัญที่สุด — ห้ามให้ UPDATE/DELETE เด็ดขาด** |

**และต้องมี sequence ด้วยเสมอ** — ทุกตารางที่ id เป็นเลขรันนิ่ง (`Candidate`, `Member`,
`User`, `AdminAuditLog`, `Ballot`) เวลา `INSERT` จะไปขอเลขถัดไปจาก sequence ของตัวเอง
ให้สิทธิ์ตารางอย่างเดียวไม่พอ:

```sql
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO fms_app;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT USAGE, SELECT ON SEQUENCES TO fms_app;
```

#### ถ้าขาดสิทธิ์ข้อไหน จะเจออาการอะไร

ตารางนี้แปลอาการที่ผู้ใช้เห็น กลับเป็นสิทธิ์ที่หายไป — อาการส่วนใหญ่ไม่ได้บอกคำว่า
"permission" ให้เลย

| อาการที่ผู้ใช้เจอ | สิทธิ์ที่ขาด |
|---|---|
| เพิ่มพรรคไม่ได้ **แต่ลบได้** | `USAGE` บน `Candidate_id_seq` (ไม่ใช่สิทธิ์ตาราง) |
| เพิ่มพรรคเปล่า ๆ ได้ แต่พอมีสมาชิกแล้วพัง | `INSERT` บน `Member` หรือ `Member_id_seq` |
| แก้ไขพรรคแล้วสมาชิกหายหมด / เซฟไม่ผ่าน | `DELETE` หรือ `INSERT` บน `Member` |
| ลบพรรคแล้วขึ้น error ทั้งที่สมาชิกหายไปแล้ว | `DELETE` บน `Candidate` |
| กดเปลี่ยนธีมแล้วเด้งกลับธีมเดิมทุกครั้ง | `UPDATE` บน `SystemConfig` |
| เปลี่ยนโหมด/เปิดผลไม่ติด | `UPDATE` บน `SystemConfig` |
| นักศึกษากดลงคะแนนแล้ว error | `INSERT Ballot` / `UPDATE ChainHead` / `UPDATE Candidate` |
| ทุกคำสั่งแอดมินพังพร้อมกัน | `INSERT` บน `AdminAuditLog` (ระบบบันทึกทุกคำสั่งก่อนทำงาน) |
| `admin.js --grant` ไม่ขึ้นชื่อในรายการ | `UPDATE` บน `User` |
| `import-students` ล้ม | `INSERT`/`UPDATE` บน `User` + sequence |

#### ตรวจให้ครบก่อนส่งมอบ

```bash
# 1. ตัวตรวจอัตโนมัติ — ลอง INSERT จริงแล้ว rollback (ครอบคลุมทั้งตารางและ sequence)
npm run preflight        # ต้องขึ้น "app can create parties/members"

# 2. หีบบัตรถูกล็อกจริง — ต้องได้เฉพาะ SELECT, INSERT
psql "<fms_migrate>" -c "SELECT privilege_type FROM information_schema.role_table_grants WHERE grantee='fms_app' AND table_name='Ballot';"

# 3. ดูสิทธิ์ทั้งหมดของบัญชีเว็บในครั้งเดียว
psql "<fms_migrate>" -c "SELECT table_name, string_agg(privilege_type, ', ' ORDER BY privilege_type) FROM information_schema.role_table_grants WHERE grantee='fms_app' GROUP BY table_name ORDER BY table_name;"
```

ผลของข้อ 3 ต้อง **ไม่ขาด** สิทธิ์ไหนที่ตารางด้านบนทำเครื่องหมาย ✓ ไว้ ถ้ามีตารางไหนหายไป
ทั้งแถว แปลว่า `ballot-grants.sql` ยังไม่ได้รัน หรือรันตอนที่ยังไม่มีตารางนั้น (ต้อง migrate
ให้เสร็จก่อนเสมอ) — ส่วนที่ **เกิน** มาได้แถวเดียวคือ `Template` ที่จะขึ้นครบทั้งสี่สิทธิ์
ตามที่ไฟล์ให้ไว้ อันนั้นไม่ใช่ความผิดพลาด · ห้ามเกินเฉพาะ `Ballot` เท่านั้น (ต้องได้แค่
`SELECT, INSERT` ตามข้อ 2)
